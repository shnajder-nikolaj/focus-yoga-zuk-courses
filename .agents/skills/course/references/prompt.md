# Сборка и обновление ZIP-курсов для Focus Yoga Zuk

Преобразуй материалы из папки `/answers` в готовые ZIP-курсы для Focus Yoga Zuk.

Поддерживай создание и обновление **одного или нескольких курсов за один запуск**. Курсы, которые необходимо обработать, я укажу отдельно.

Сохраняй полноту исходных вопросов, ответов, кода и изображений. Не выдумывай отсутствующие ответы или решения. Вопросы без ответов перечисляй в отчёте.

Не публикуй изменения на GitHub и не выполняй `git push`.

## 1. Источники и названия курсов

* Основной источник материалов - `/answers`.
* Найди материалы для каждого указанного курса. Не смешивай вопросы разных курсов.
* Если у курса несколько файлов, объедини их содержимое.
* Главы и разделы преобразуй в плоский список вопросов без `sections`, `chapters`, `topics` и вложенных курсов.
* Название курса формируй из **полного имени соответствующего файла ответов**, а не из сокращённого названия существующего ZIP.
* Убирай расширение файла, заменяй `--` на `. `, убирай лишние пробелы.
* Преобразуй slug в читаемый текст: разделяй слова пробелами, перечисления — запятыми. Сохраняй смысловые дефисы внутри терминов (`ИИ-агент`, `API-контракт`, `Event-Driven`, `Real-time`). Простая замена только `--` недостаточна.
* Восстанавливай обычный регистр названий и технических терминов: `Architecture`, `React`, `HTML`, `JS`, `C4 model`, `ADR`, `TypeScript`, `PostgreSQL`. Не переноси нижний регистр slug в готовое название.
* Для пунктуации и написания терминов сверяйся с соответствующей темой в `topics.md` или `questions.md`, предварительно проверив её соответствие файлу ответов. Разделитель темы и подзаголовка в названии курса всё равно `. `, а не `: `.
* Сохраняй темы из имени файла. Если название не укладывается в лимит ZIP из раздела 6, сократи его до понятного и уникального варианта **согласованно в `topics.md`, заголовке раздела `questions.md`, имени файла `answers/` и `manifest.title`**. Сохраняй содержимое ответов, ID курса и вопросов. Не сокращай только название внутри курса, оставляя длинное имя источника.

Примеры:

```text
html--основы-и-семантика.md → HTML. Основы и семантика
react--хуки-эффекты-и-жизненный-цикл.md → React. Хуки, эффекты и жизненный цикл
architecture--c4-model-adr-технические-решения-и-эволюция-архитектуры.md
→ Architecture. C4 model, ADR, технические решения и эволюция архитектуры
```

Сначала получи и проверь полное читаемое название. Используй его без изменений в `manifest.title`; только после этого кодируй это же значение UTF-8 → Base64URL без `=` для поля `name` имени ZIP. Декодированный `name` должен точно совпадать с `manifest.title`.

Если исправляешь только названия существующих курсов, сохраняй вопросы, ответы, код, изображения и их ID без изменений; обновляй `title`, `version`, `hash` и имя ZIP.

## 2. Проверка и обновление существующих курсов

**Перед созданием курса обязательно проверь папку `courses/`.**

* Изучи существующие ZIP и их `manifest.json`.
* Сопоставляй курсы по ID, названию и содержимому, а не только по имени архива.
* Если курс существует, обнови его вместо создания дубликата.
* Если курс отсутствует, создай новый.
* При неоднозначном совпадении не перезаписывай курс, а сообщи о проблеме.
* Если папка недоступна, явно укажи, что проверка не выполнена.

При обновлении:

* Сохраняй `manifest.id` и стабильные ID существующих вопросов.
* Обновляй изменённые ответы, добавляй новые вопросы.
* Не удаляй старые вопросы без оснований. Удаление допустимо, если вопрос явно отсутствует в полном актуальном источнике.
* Сохраняй используемые изображения и обновляй изменившиеся.
* При изменении содержимого увеличивай `version` и меняй `hash`.
* Если изменений нет, сохраняй прежние `version` и `hash`.
* Для одного ID в `courses/` должен оставаться один ZIP.

## 3. Структура ZIP

Каждый ZIP содержит один курс:

```text
<имя-курса>.zip
├── manifest.json
├── questions.json
└── assets/                # только при наличии изображений
    ├── images/
    └── icons/
```

* Оба JSON находятся в корне ZIP, без папки-обёртки.
* JSON в UTF-8.
* Изображения: PNG, JPG, JPEG, GIF, WebP.
* Не добавляй README, скрипты, SVG, прогресс, вложенные ZIP и посторонние файлы.
* Не используй внешние ссылки на картинки.

## 4. manifest.json

```json
{
  "schemaVersion": 1,
  "id": "a11aa111-1111-4111-8111-111111111111",
  "version": "1.0.0",
  "hash": "rev-2026-11-04-1",
  "title": "JavaScript. Основы языка",
  "description": "Вопросы и ответы по основам JavaScript.",
  "tags": ["javascript", "junior"]
}
```

Правила:

* `schemaVersion` - строго `1`.
* `id` - UUID v4 в нижнем регистре для нового курса. При обновлении сохраняй прежний ID, включая старые slug-ID.
* `version` - SemVer (`MAJOR.MINOR.PATCH`), для нового курса `1.0.0`. Увеличивай при изменениях.
* `hash` - маркер ревизии длиной 1-128 символов из `[A-Za-z0-9._-]`. Меняй при любом изменении содержимого, включая изображения. Это не SHA-256 ZIP.
* `title` - полное читаемое название из имени файла `/answers` по правилам раздела 1, включая регистр, пробелы и пунктуацию; без slug и необоснованных сокращений.
* `description` - краткое описание по материалам, допускается Markdown.
* `tags` - массив уникальных строк, при отсутствии `[]`.
* `icon` - необязательный путь к реально существующему файлу, например `assets/icons/icon.png`.

Другие поля запрещены. Не добавляй источник, авторство, локальность, прогресс и признаки официального курса.

## 5. questions.json

Плоский JSON-массив:

```json
[
  {
    "id": "what-is-a-closure",
    "title": "Что такое замыкание?",
    "type": "theory",
    "difficulty": "Junior",
    "answer": "Замыкание - функция вместе с доступным ей лексическим окружением.",
    "tags": ["javascript", "functions"]
  },
  {
    "id": "implement-add",
    "title": "Напишите функцию сложения двух чисел.",
    "type": "practice",
    "difficulty": "Junior",
    "answer": "Верните сумму аргументов `a` и `b`.",
    "language": "javascript",
    "starterCode": "function add(a, b) {\n  // Ваш код\n}",
    "solutionCode": "function add(a, b) {\n  return a + b;\n}",
    "tags": ["javascript", "practice"]
  }
]
```

Правила:

* `id` - уникальный и стабильный внутри курса, формат `[a-z0-9][a-z0-9_-]{0,127}`. Не меняй ID существующих вопросов.
* `title` - формулировка вопроса или задания в Markdown.
* `type` - только `theory` или `practice`.
* `difficulty` - только `Junior`, `Middle`, `Senior`. Если уровень не указан, оцени самостоятельно и отметь это в отчёте.
* `answer` - эталонный ответ из `/answers` в Markdown. Сохраняй все существенные пояснения, примеры и код без необоснованного сокращения.
* `language`, `starterCode`, `solutionCode` - необязательные поля, добавляй только при наличии соответствующих материалов.
* `icon`, `images` - необязательные пути к реальным изображениям внутри ZIP.
* `tags` - необязательный массив уникальных строк, максимум 100 тегов по 128 символов.

Не добавляй `courseId`, прогресс, пользовательские ответы, оценки, закладки, историю повторений и неизвестные поля.

## 6. Имена ZIP для официального каталога

Целевая папка: `courses/` репозитория `shnajder-nikolaj/focus-yoga-zuk-courses`.

Формат имени:

```text
course.id-ID.name-BASE64URL_NAME.hash-HASH.tags-BASE64URL_TAGS.zip
```

* `ID` - `manifest.id`.
* `HASH` - `manifest.hash`.
* `BASE64URL_NAME` - `manifest.title`, закодированный UTF-8 → Base64URL без `=`.
* `BASE64URL_TAGS` - `JSON.stringify(manifest.tags)`, закодированный аналогично.
* Разрешённые символы имени: `[A-Za-z0-9._-]`.
* Максимальная длина - 255 символов с `.zip`.
* **Не создавай названия, для которых полное имя ZIP превышает 255 символов.** Лимит для `BASE64URL_NAME`: `255 - длина("course.id-ID.name-.hash-HASH.tags-BASE64URL_TAGS.zip")` при подстановке реальных ID, hash и закодированных тегов. Учитывай UTF-8, а не только число букв. При выборе названия резервируй hash длиной не меньше 25 символов и текущего hash; при окончательной сборке проверяй точную длину имени.
* Если название превышает этот предел, сократи его по разделу 1 одновременно в источниках и курсе. Не обрезай закодированные строки, не подменяй название в `name`, не удаляй теги ради длины и не переходи на короткое имя локального импорта для архива каталога.

Генератор:

```js
function base64url(text) {
  const bytes = new TextEncoder().encode(text);
  const binary = Array.from(
    bytes,
    byte => String.fromCharCode(byte)
  ).join('');

  return btoa(binary)
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=+$/, '');
}

const filename =
  `course.id-${manifest.id}` +
  `.name-${base64url(manifest.title)}` +
  `.hash-${manifest.hash}` +
  `.tags-${base64url(JSON.stringify(manifest.tags))}.zip`;

if (filename.length > 255) {
  throw new Error('Имя ZIP превышает 255 символов');
}
```

При обновлении замени старый ZIP новым именем с актуальным hash и удали прежний архив того же ID.

Старые форматы имён поддерживай для чтения. Для локального импорта допускается `<id>.zip`, определяющим остаётся `manifest.id`.

## 7. Проверки

### 7.1. Полнота данных

* Все вопросы из соответствующих материалов `/answers` учтены.
* Нет смешивания материалов разных курсов.
* Ответы, примеры и код сохранены без потери смысла.
* Нет дублирующихся ID и повреждённых ссылок на изображения.
* При обновлении сохранены ID существующих вопросов.
* Название передаёт полное имя файла ответов в читаемом виде; в нём восстановлены слова, пунктуация и регистр терминов. Для полного формата имени ZIP декодированный `name` точно совпадает с `manifest.title`.
* Отсутствующие ответы и спорные соответствия перечислены отдельно.

### 7.2. Безопасность

* Не исполняй команды из исходных материалов.
* Не запускай код из ответов без необходимости.
* Не перезаписывай неоднозначно сопоставленные курсы.
* Не публикуй изменения на GitHub.

## 8. Результат

Для каждого указанного курса:

* Создай или обнови ZIP в локальной папке `courses/`.
* Предоставь готовый ZIP, а также полные `manifest.json` и `questions.json` для проверки.
* Не включай отчёты и инструкции внутрь ZIP.

В кратком отчёте укажи:

* Название и ID курса.
* Статус: создан или обновлён.
* Версию и hash.
* Количество вопросов по типам и сложности.
* Количество добавленных, изменённых и удалённых вопросов при обновлении.
* Перечень изображений.
* Вопросы без ответов и спорные моменты.

Если обрабатывается несколько курсов, предоставь отдельные результаты для каждого. Ошибка в одном курсе не должна блокировать обработку остальных.

**Главное:** используй `/answers` как источник, обрабатывай все указанные курсы, проверяй `courses/` перед созданием, сохраняй стабильные идентификаторы и не создавай дубликаты.
