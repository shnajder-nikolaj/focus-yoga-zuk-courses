# Какие типы данных есть в JavaScript?

В JavaScript существует 8 типов данных: 7 примитивных и 1 объектный.

Примитивные типы:

- `string` - строки
- `number` - числа, включая `NaN`, `Infinity` и `-Infinity`
- `bigint` - целые числа произвольной точности
- `boolean` - логические значения `true` и `false`
- `undefined` - отсутствие присвоенного значения
- `null` - намеренное отсутствие значения
- `symbol` - уникальные идентификаторы

Объектный тип:

\- `object` - объекты, массивы, функции, даты, коллекции и другие структуры

Функции технически являются объектами, хотя `typeof` возвращает для них `"function"`.

# Чем примитив отличается от объекта?

Примитив - неизменяемое значение, которое сравнивается по значению. При присваивании переменной копируется само значение.

Объект - значение с идентичностью, которое может содержать свойства. При присваивании копируется ссылка на объект, а не создаётся его копия.

```
let a = 10;
let b = a;
b = 20;

console.log(a); // 10

const obj1 = { x: 10 };
const obj2 = obj1;

obj2.x = 20;

console.log(obj1.x); // 20
```

Объекты сравниваются по идентичности: `{} === {}` возвращает `false`, поскольку созданы два разных объекта.

Примитивы неизменяемы, а объекты обычно изменяемы. Однако объект можно сделать неизменяемым на верхнем уровне с помощью `Object.freeze()`.

# Что означает динамическая типизация?

Динамическая типизация означает, что тип принадлежит значению, а не переменной, и определяется во время выполнения программы.

Одна переменная может последовательно содержать значения разных типов:

```
let value = 10;
value = "hello";
value = true;
```

JavaScript не требует заранее объявлять тип переменной. Проверка допустимости операций происходит во время выполнения, а некоторые операции автоматически преобразуют типы.

Динамическая типизация не означает отсутствие типов - каждое значение имеет конкретный тип.

# Чем `null` отличается от `undefined`?

Оба значения обозначают отсутствие данных, но имеют разный смысл.

- `undefined` - значение не было определено или предоставлено. Например, переменная объявлена без инициализации, свойство отсутствует или функция ничего не возвращает.
- `null` - явное значение, обычно используемое разработчиком для обозначения намеренного отсутствия данных.

```
let a;
let b = null;

console.log(a); // undefined
console.log(b); // null
```

Особенности сравнения:

```
null == undefined;  // true
null === undefined; // false
```

Также `typeof undefined` возвращает `"undefined"`, а `typeof null` - `"object"`.

# Почему `typeof null` возвращает `object`?

Это историческая ошибка JavaScript, сохранившаяся ради обратной совместимости.

В ранней реализации JavaScript значения кодировались с использованием тегов типов. Представление `null` совпадало с кодировкой, которую проверка `typeof` интерпретировала как объект.

Позднее поведение закрепилось в стандарте ECMAScript. Его изменение могло бы нарушить существующий код.

При этом `null` - примитив, а не объект. Для проверки используется строгое сравнение:

```
value === null;
```

# Что такое `NaN` и как его корректно проверить?

`NaN` (Not a Number) - специальное значение типа `number`, обозначающее неопределённый или непредставимый числовой результат, например `0 / 0` или `Number("abc")`.

Особенность `NaN` - оно не равно самому себе:

```
NaN === NaN; // false
```

Для проверки рекомендуется `Number.isNaN()`:

```
Number.isNaN(NaN);   // true
Number.isNaN("abc"); // false
```

Глобальная функция `isNaN()` сначала приводит аргумент к числу, поэтому может давать неожиданные результаты:

```
isNaN("abc");        // true
Number.isNaN("abc"); // false
```

Также `Object.is(NaN, NaN)` возвращает `true`.

# Почему `0.1 + 0.2` не равно точно `0.3`?

JavaScript хранит обычные числа в формате IEEE 754 double precision - 64-битных чисел с плавающей точкой.

Большинство десятичных дробей, включая `0.1` и `0.2`, нельзя представить точно конечной двоичной дробью. Поэтому они сохраняются с небольшими погрешностями.

При сложении погрешности приводят к результату:

```
0.1 + 0.2; // 0.30000000000000004
```

Для приблизительного сравнения можно использовать допустимую погрешность:

```
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true
```

`Number.EPSILON` подходит для некоторых сравнений чисел около единицы, но не является универсальной погрешностью. Для произвольных значений допуск нужно выбирать с учётом масштаба и требований к точности.

Для финансовых расчётов часто используют целые значения минимальных денежных единиц или библиотеки десятичной арифметики.

# Чем `==` отличается от `===` и когда возникает неявное приведение?

`===` (strict equality) сравнивает значения без приведения типов.

`==` (abstract equality) может автоматически преобразовывать операнды по правилам ECMAScript.

```
5 == "5";    // true
5 === "5";   // false

false == 0;  // true
false === 0; // false

null == undefined;  // true
null === undefined; // false
```

При `==` приведение происходит по определённым правилам:

- Число и строка - строка преобразуется в число
- Boolean и другое значение - Boolean преобразуется в число (`true` в `1`, `false` в `0`)
- Объект и примитив - объект обычно преобразуется в примитив
- `null` и `undefined` равны друг другу при `==`, но не равны другим значениям

Например:

```
[] == false; // true
```

Пустой массив преобразуется в пустую строку, затем в `0`, а `false` тоже преобразуется в `0`.

В большинстве случаев рекомендуется `===`, поскольку его поведение предсказуемее. Осмысленное исключение - `value == null`, позволяющее одновременно проверить `null` и `undefined`.

# Какие значения являются falsy?

Falsy - значения, которые преобразуются в `false` в логическом контексте.

В JavaScript к ним относятся:

- `false`
- `0` и `-0`
- `0n` (`BigInt`)
- `NaN`
- `""` (пустая строка)
- `null`
- `undefined`

Дополнительно существует историческое браузерное исключение - `document.all`.

Все остальные значения являются truthy, включая пустые массивы, пустые объекты и строку `"false"`.

```
Boolean([]);      // true
Boolean({});      // true
Boolean("false"); // true
Boolean("0");     // true
```

# Чем `||` отличается от `??`?

Оба оператора могут использоваться для выбора резервного значения, но проверяют разные условия.

`||` (logical OR) возвращает правый операнд, если левый является falsy.

`??` (nullish coalescing) возвращает правый операнд только тогда, когда левый равен `null` или `undefined`.

```
0 || 100;  // 100
0 ?? 100;  // 0

"" || "default"; // "default"
"" ?? "default"; // ""

null ?? "default"; // "default"
```

`??` предпочтителен, когда `0`, `false` и `""` являются допустимыми значениями, которые нельзя заменять резервными.

Операторы `??` и `||`/`&&` нельзя смешивать в одном выражении без явных скобок.

# Как работают `&&`, `||` и short-circuit evaluation?

Short-circuit evaluation - механизм короткого замыкания, при котором второй операнд вычисляется только при необходимости.

`&&` (AND):

- Если левый операнд falsy, возвращает его без вычисления правого
- Иначе возвращает правый операнд

`||` (OR):

- Если левый операнд truthy, возвращает его без вычисления правого
- Иначе возвращает правый операнд

```
0 && console.log("Hello"); // 0, log не вызывается

"Hello" || "World"; // "Hello"

"Hello" && 42; // 42
```

Операторы возвращают значения операндов, а не обязательно `boolean`.

Короткое замыкание часто используется для условного выполнения операций:

```
isAuthorized && loadProfile();
```

`loadProfile()` вызовется только при truthy-значении `isAuthorized`.

# Что делает оператор `?.`?

Optional chaining (`?.`) позволяет безопасно обращаться к свойствам или вызывать методы, если промежуточное значение может быть `null` или `undefined`.

```
const user = null;

user?.name;           // undefined
user?.profile?.email; // undefined
```

Поддерживаются три формы:

- `obj?.prop` - доступ к свойству
- `obj?.[key]` - вычисляемый доступ к свойству
- `fn?.()` - необязательный вызов функции

Если проверяемое значение равно `null` или `undefined`, вычисление соответствующей цепочки прекращается и возвращается `undefined`.

Важно: оператор не защищает от всех ошибок. Например, `obj.method?.()` выбросит `TypeError`, если `method` существует, но не является функцией.

Также `?.` не позволяет присваивать значения:

```
user?.name = "Alex"; // SyntaxError
```

# Что означает `Object.is()` и чем он отличается от `===`?

`Object.is()` сравнивает два значения по алгоритму SameValue, без приведения типов.

Почти всегда его результат совпадает с `===`, кроме двух случаев:

```
NaN === NaN;         // false
Object.is(NaN, NaN); // true

0 === -0;         // true
Object.is(0, -0); // false
```

При сравнении объектов оба механизма проверяют идентичность, а не содержимое:

```
Object.is({}, {}); // false
```

`Object.is()` полезен, когда необходимо различать `+0` и `-0` или корректно сравнивать `NaN`. Например, React использует сравнение на основе `Object.is()` при проверке изменений состояния.

# Как работают приведения `String()`, `Number()` и `Boolean()`?

Эти функции выполняют явное преобразование значения к соответствующему примитивному типу.

`String()` преобразует значение в строковое представление:

```
String(123);       // "123"
String(null);      // "null"
String(undefined); // "undefined"
String([1, 2]);    // "1,2"
String({});        // "[object Object]"
```

Для объектов преобразование может использовать `Symbol.toPrimitive`, `toString()` или `valueOf()`.

`Number()` преобразует значение в число:

```
Number("123"); // 123
Number("");    // 0
Number(null);  // 0
Number(true);  // 1
Number(false); // 0

Number(undefined); // NaN
Number("hello");   // NaN
```

Если строка не соответствует допустимому числовому представлению, результатом будет `NaN`.

`Boolean()` преобразует значение в логический тип по правилам truthy/falsy:

```
Boolean(0);       // false
Boolean("");      // false
Boolean(null);    // false

Boolean("false"); // true
Boolean([]);      // true
Boolean({});      // true
```

Важно: `Boolean()` не анализирует смысл строки. Любая непустая строка является truthy.

# Чем `parseInt()` отличается от `Number()` и `parseFloat()`?

Все три функции могут преобразовывать строки в числа, но используют разные правила.

`Number()` пытается преобразовать всю строку в число. Если строка содержит недопустимые символы, возвращает `NaN`.

`parseInt()` считывает целое число с начала строки и прекращает чтение при первом недопустимом символе. Позволяет указать систему счисления.

`parseFloat()` аналогично считывает число с начала строки, но поддерживает дробную часть и экспоненциальную запись.

```
Number("12.5px");     // NaN
parseInt("12.5px", 10); // 12
parseFloat("12.5px");  // 12.5
```

Другие отличия:

```
Number("");        // 0
parseInt("", 10);  // NaN
parseFloat("");    // NaN

Number("1e3");       // 1000
parseInt("1e3", 10);  // 1
parseFloat("1e3");   // 1000
```

`parseInt()` не округляет число, а отбрасывает часть записи после первого недопустимого символа. Для десятичных чисел рекомендуется явно указывать основание `10`.

# Что такое `BigInt` и где он нужен?

`BigInt` - примитивный тип для работы с целыми числами произвольной точности, не ограниченный диапазоном безопасных целых чисел `number`.

Создаётся добавлением `n` к целочисленному литералу или через `BigInt()`:

```
const a = 9007199254740993n;
const b = BigInt("9007199254740993");

a === b; // true
```

Используется для больших идентификаторов, точной целочисленной арифметики, криптографических вычислений и других задач, где недостаточно точности `number`.

Основные ограничения:

- Нельзя напрямую смешивать `bigint` и `number` в арифметических операциях: `1n + 1` выбросит `TypeError`
- Деление отбрасывает дробную часть: `5n / 2n` возвращает `2n`
- Методы `Math` не поддерживают `BigInt`
- `JSON.stringify()` не сериализует `BigInt` по умолчанию

`BigInt` не подходит для дробных чисел. Также важно создавать большие значения из строк или литералов с `n`, поскольку преобразование уже неточного `number` не восстановит потерянную точность.

# Что такое `Symbol` и зачем нужны well-known symbols?

`Symbol` - примитивный тип, создающий уникальные значения, которые часто используются в качестве ключей свойств объектов.

```
const a = Symbol("id");
const b = Symbol("id");

a === b; // false
```

Даже одинаковое описание не делает символы равными.

Символы помогают избегать конфликтов имён свойств, особенно при расширении объектов сторонними библиотеками.

Well-known symbols - предопределённые стандартом символы, с помощью которых объекты могут настраивать своё поведение в механизмах JavaScript.

Примеры:

- `Symbol.iterator` - определяет поведение объекта при итерации через `for...of` и другие механизмы
- `Symbol.asyncIterator` - определяет асинхронную итерацию
- `Symbol.toPrimitive` - управляет преобразованием объекта в примитив
- `Symbol.toStringTag` - позволяет настраивать строковый тег объекта
- `Symbol.hasInstance` - позволяет настраивать поведение `instanceof`

Например, объект можно сделать итерируемым, реализовав метод с ключом `[Symbol.iterator]`.

Отдельно существует `Symbol.for("key")`, который возвращает символ из глобального реестра символов, позволяя повторно получать один и тот же символ по строковому ключу.

# В чём различие `typeof`, `instanceof` и `Array.isArray()`?

Эти механизмы проверяют разные характеристики значений.

`typeof` - возвращает строку с типом значения.

```
typeof 42;       // "number"
typeof "hello";  // "string"
typeof null;     // "object"
typeof [];       // "object"
typeof (() => {}); // "function"
```

Подходит для проверки примитивных типов и функций, но не позволяет точно определить большинство разновидностей объектов.

`instanceof` - обычно проверяет, присутствует ли `Constructor.prototype` в цепочке прототипов объекта.

```
[] instanceof Array;    // true
new Date() instanceof Date; // true
```

Не гарантирует принадлежность объекта конкретному классу по факту создания. Результат зависит от цепочки прототипов и может быть переопределён через `Symbol.hasInstance`.

Кроме того, `instanceof` может некорректно подходить для проверок объектов между разными JavaScript-контекстами (realms), например между iframe.

`Array.isArray()` - специальная проверка, действительно ли значение является массивом.

```
Array.isArray([]); // true
Array.isArray({}); // false
```

Она работает корректно даже для массивов из других realms.

Для проверки массивов рекомендуется `Array.isArray()`, для примитивов - `typeof`, а для проверки прототипного наследования - `instanceof`.

# Что происходит при сложении строки и числа?

Оператор `+` в JavaScript выполняет либо числовое сложение, либо конкатенацию строк.

Сначала операнды преобразуются в примитивы. Если хотя бы один из них является строкой, выполняется конкатенация с преобразованием другого операнда в строку.

```
5 + "10"; // "510"
"5" + 10; // "510"

5 - "2";  // 3
```

В отличие от `+`, оператор `-` всегда пытается выполнить числовую операцию (с учётом правил для `BigInt`).

Порядок вычисления влияет на результат:

```
1 + 2 + "3"; // "33"
"1" + 2 + 3; // "123"
```

Операторы обрабатываются слева направо: сначала `1 + 2` даёт `3`, затем число объединяется со строкой.

Важно: не все типы допускают такое преобразование. Например, `1n + 2` выбросит `TypeError`, поскольку нельзя смешивать `BigInt` и `Number` в арифметическом сложении.

# В чём отличие statement от expression?

Expression (выражение) - конструкция, которая вычисляется и даёт значение.

```
2 + 3
user.name
isActive ? "yes" : "no"
```

Выражения можно использовать внутри других выражений, присваиваний, аргументов функций и других конструкций.

Statement (инструкция) - конструкция, которая определяет действие или управляет выполнением программы.

```
if (isActive) {
  console.log("Active");
}

for (let i = 0; i < 3; i++) {
  console.log(i);
}
```

Инструкции не обязательно создают значение, которое можно использовать как часть другого выражения.

Например, `if` - инструкция, поэтому её нельзя использовать непосредственно для присваивания:

```
const result = condition ? "yes" : "no";
```

Здесь применяется тернарный оператор, который является выражением.

При этом некоторые выражения могут использоваться как самостоятельные инструкции (expression statements), например вызовы функций или присваивания.

# Когда использовать `switch`, а когда `if/else`?

`switch` удобен, когда одно выражение необходимо сравнить с несколькими конкретными значениями.

```
switch (status) {
  case "loading":
    showLoader();
    break;

  case "success":
    showContent();
    break;

  default:
    showError();
}
```

Особенности `switch`:

- Сравнивает значение с `case` по принципу строгого равенства, без приведения типов
- Использует `break` для выхода из конструкции
- Без `break` выполнение может продолжиться в следующих ветках (fallthrough)
- `default` выполняется, если подходящая ветка не найдена

`if/else` лучше подходит для сложных логических условий, диапазонов и комбинаций проверок.

```
if (age < 18) {
  return "minor";
} else if (age >= 65) {
  return "senior";
}
```

Главный критерий выбора - характер условий: сравнение одного значения с несколькими вариантами или проверка произвольных логических выражений.

# Какие особенности есть у `try/catch/finally`?

`try/catch/finally` используется для обработки исключений и выполнения завершающих действий.

- `try` - выполняет код, который может выбросить исключение
- `catch` - перехватывает исключение и позволяет его обработать
- `finally` - выполняется после `try` и возможного `catch`, независимо от того, возникло исключение или нет

```
try {
  riskyOperation();
} catch (error) {
  console.error(error);
} finally {
  cleanup();
}
```

Важные особенности:

1\. `finally` выполняется даже при `return`.

Если функция завершает выполнение через `return` внутри `try`, блок `finally` выполнится перед фактическим возвратом значения.

Если сам `finally` содержит `return` или выбрасывает исключение, он может переопределить предыдущий результат или исключение.

2\. `try/catch` не перехватывает автоматически ошибки из асинхронных операций.

Например, исключение внутри `setTimeout` нельзя перехватить внешним `try/catch`, поскольку callback выполняется позднее, в другом контексте выполнения.

Для обработки ошибок промисов используется `.catch()` или `try/catch` вместе с `await`.

3\. Выбрасывать можно любое значение.

```
throw "error";
throw 123;
throw new Error("Failed");
```

Рекомендуется использовать объекты `Error` и их подклассы, поскольку они содержат дополнительную информацию, включая стек вызовов.

# Что означает strict mode и как он влияет на выполнение кода?

Strict mode - строгий режим JavaScript, который запрещает некоторые потенциально опасные конструкции и делает часть скрытых ошибок явными.

В обычных скриптах и функциях активируется директивой:

```
"use strict";
```

В ES-модулях и телах классов строгий режим включён по умолчанию.

Основные изменения:

1\. Запрещает неявное создание глобальных переменных.

```
"use strict";

value = 10; // ReferenceError
```

2\. Превращает некоторые молчаливые ошибки в исключения.

Например, попытка изменить свойство, доступное только для чтения, выбросит `TypeError`.

3\. Изменяет поведение `this` в обычных функциях.

При вызове обычной функции без контекста `this` остаётся `undefined`, а не автоматически преобразуется в глобальный объект.

4\. Запрещает некоторые конструкции.

Например, использование `with`, а также дублирование имён параметров обычной функции.

Строгий режим помогает обнаруживать ошибки раньше и делает поведение кода предсказуемее. При этом он не добавляет статическую типизацию и не устраняет все потенциальные ошибки выполнения.

# Чем передача примитивов и объектов в аргументы функции отличается на практике?

В JavaScript все аргументы передаются по значению (pass by value).

Разница заключается в том, что для примитива передаётся копия самого значения, а для объекта - копия ссылки на объект.

Примитив:

```
function change(value) {
  value = 100;
}

let x = 10;
change(x);

console.log(x); // 10
```

Изменение параметра не влияет на переменную снаружи функции.

Объект:

```
function change(obj) {
  obj.value = 100;
}

const data = { value: 10 };
change(data);

console.log(data.value); // 100
```

Функция получает ссылку на тот же объект, поэтому изменение его свойств видно снаружи.

Однако переназначение параметра не изменяет внешнюю переменную:

```
function change(obj) {
  obj = { value: 100 };
}

const data = { value: 10 };
change(data);

console.log(data.value); // 10
```

Следовательно, JavaScript не использует передачу объектов по ссылке в классическом смысле. Передаётся значение ссылки, поэтому можно изменять содержимое объекта, но нельзя переназначить переменную вызывающего кода через параметр.

# Какие ограничения есть у чисел типа `number` и `Number.MAX_SAFE_INTEGER`?

Тип `number` использует формат IEEE 754 double precision с 64-битным представлением.

Его основные ограничения связаны с точностью, диапазоном и представлением дробных чисел.

1\. Ограниченная точность целых чисел.

Для хранения значащих цифр используется 53 бита точности, включая неявный старший бит.

Максимальное безопасное целое:

```
Number.MAX_SAFE_INTEGER; // 9007199254740991
```

Это \\(2^{53}-1\\).

За пределами безопасного диапазона не все целые числа можно представить точно:

```
9007199254740992 === 9007199254740993; // true
```

Число `9007199254740993` округляется до ближайшего представимого значения.

Для проверки используется `Number.isSafeInteger()`.

2\. Погрешности дробных чисел.

Из-за двоичного формата некоторые десятичные дроби представляются приблизительно:

```
0.1 + 0.2 === 0.3; // false
```

Для задач, требующих точной десятичной арифметики, обычно применяют специализированные библиотеки или целочисленное представление.

3\. Ограниченный диапазон значений.

```
Number.MAX_VALUE; // ~1.7976931348623157e+308
Number.MIN_VALUE; // ~5e-324
```

`Number.MAX_VALUE` - максимальное конечное положительное значение.

`Number.MIN_VALUE` - минимальное положительное значение, отличное от нуля, а не самое отрицательное число.

При переполнении диапазона результатом может стать `Infinity` или `-Infinity`, а при слишком малой абсолютной величине - `0` или `-0`.

4\. Специальные значения.

Тип `number` поддерживает `NaN`, `Infinity`, `-Infinity`, `+0` и `-0`.

Они имеют особенности сравнения и арифметических операций.

Для точных больших целых чисел используется `BigInt`. Для дробных вычислений, требующих точности, необходим выбор подходящего представления и алгоритма, поскольку обычный `number` не гарантирует точную десятичную арифметику.
