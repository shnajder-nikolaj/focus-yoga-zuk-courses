
# Какие элементы используются для построения HTML-форм?

Основной элемент - `<form>`. Он объединяет поля ввода и определяет способ отправки данных через атрибуты `action`, `method` и `enctype`.

Основные элементы формы:

- `<input>` - однострочные поля, переключатели, флажки, загрузка файлов и другие элементы управления
- `<textarea>` - многострочный ввод текста
- `<select>` и `<option>` - выпадающий список и его варианты
- `<button>` - кнопка отправки, сброса или произвольного действия
- `<label>` - текстовая метка элемента управления
- `<fieldset>` и `<legend>` - группировка связанных полей и название группы
- `<datalist>` - список предлагаемых значений для поля ввода
- `<output>` - отображение результата вычисления или действия

Для отправки значения элемента обычно необходим атрибут `name`. Без него значение не включается в стандартные данные формы.

# Как связать `label` с полем ввода?

Существует два основных способа:

**Явная связь** - атрибут `for` у `<label>` соответствует `id` поля:

```html
<label for="email">Email</label>
<input id="email" name="email" type="email">
```

**Неявная связь** - поле размещается внутри `<label>`:

```html
<label>
  Email
  <input name="email" type="email">
</label>
```

Связь обеспечивает:

- Фокусировку поля при нажатии на метку
- Увеличение области нажатия для чекбоксов и радиокнопок
- Корректное определение названия поля скринридерами

Для явной связи `id` должен быть уникальным в документе. `placeholder` не заменяет `<label>`, поскольку исчезает при вводе и не обеспечивает полноценную доступность.

# Какие типы `input` существуют и чем они различаются?

Атрибут `type` определяет назначение поля, его поведение, интерфейс и встроенные правила валидации.

**Текстовые поля:**

- `text` - обычный текст, используется по умолчанию
- `password` - скрывает отображаемые символы
- `email` - проверяет синтаксис email
- `url` - проверяет синтаксис абсолютного URL
- `tel` - ввод телефона без встроенной проверки его формата
- `search` - поле поискового запроса

**Числа и диапазоны:**

- `number` - числовое значение с возможностью ограничений `min`, `max`, `step`
- `range` - выбор числового значения с помощью ползунка

**Дата и время:**

- `date` - дата
- `time` - время
- `datetime-local` - локальная дата и время без часового пояса
- `month` - месяц и год
- `week` - неделя и год

**Выбор значений:**

- `checkbox` - независимый флажок
- `radio` - выбор одного варианта из группы с одинаковым `name`
- `color` - выбор цвета
- `file` - выбор файлов

**Управление формой:**

- `submit` - отправка формы
- `reset` - сброс значений к исходным
- `button` - кнопка без встроенного действия
- `image` - графическая кнопка отправки формы
- `hidden` - скрытое поле, значение которого может отправляться с формой

Различия касаются не только интерфейса. Например, `email` проверяет формат, `number` поддерживает числовые ограничения, а `checkbox` отправляет значение только в отмеченном состоянии.

Важно: `type="number"` не подходит для номеров телефонов, индексов и идентификаторов, даже если они состоят из цифр. Для них обычно используют `type="text"` с `inputmode="numeric"`.

# Как работают атрибуты `required`, `min`, `max`, `step` и `pattern`?

Эти атрибуты задают ограничения, которые браузер использует при нативной валидации.

- `required` - требует заполнения поля или выбора значения. Для группы `radio` с одинаковым `name` достаточно выбрать один вариант
- `min` - минимальное допустимое значение для поддерживаемых числовых и временных типов
- `max` - максимальное допустимое значение
- `step` - допустимый шаг значения относительно базы шага
- `pattern` - регулярное выражение для проверки строковых значений поддерживаемых типов `input`

Пример:

```html
<input
  type="number"
  min="0"
  max="100"
  step="5"
  required
>
```

Поле принимает значения от `0` до `100`, кратные шагу `5` относительно `min`.

Для `pattern` используется синтаксис JavaScript-регулярных выражений. Совпадать должна вся строка, а не её отдельная часть.

```html
<input
  type="text"
  pattern="[A-Z]{3}[0-9]{2}"
  required
>
```

Допустимое значение - `ABC12`.

Важные особенности:

- `pattern` не делает поле обязательным. Пустая строка допустима без `required`
- `step="any"` отключает проверку кратности шагу
- `min` и `max` ограничивают значения, а не длину текста. Для длины существуют `minlength` и `maxlength`
- Ограничения работают только для поддерживаемых типов элементов
- Клиентская валидация не заменяет серверную, поскольку её можно обойти

# Чем отличаются `disabled` и `readonly`?

Оба атрибута запрещают пользователю изменять значение, но ведут себя по-разному.

| Поведение                    | `disabled`                       | `readonly`                                       |
|------------------------------|----------------------------------|--------------------------------------------------|
| Изменение пользователем      | Запрещено                        | Запрещено                                        |
| Получение фокуса             | Нет                              | Да                                               |
| Отправка значения с формой   | Нет                              | Да                                               |
| Участие в нативной валидации | Нет                              | Нет                                              |
| Поддержка                    | Большинство элементов управления | Текстовые и некоторые другие `input`, `textarea` |

`disabled` полностью отключает элемент управления. Его значение не попадает в `FormData`.

`readonly` оставляет поле доступным для фокусировки, выделения и копирования текста. Значение продолжает отправляться с формой.

`readonly` нельзя использовать для `select`, `checkbox` и `radio`.

Оба атрибута не являются механизмом безопасности: значения можно изменить через JavaScript или отправить напрямую на сервер.

# Как работают `name`, `value`, `defaultValue` и `placeholder`?

**`name`** - имя поля, под которым его значение передаётся при отправке формы.

**`value`** - значение поля. У `<input>` HTML-атрибут `value` обычно задаёт начальное значение, а DOM-свойство `value` отражает текущее.

**`defaultValue`** - DOM-свойство, отражающее исходное значение поля. Это не стандартный HTML-атрибут. В React `defaultValue` также используется для задания начального значения неконтролируемого поля.

**`placeholder`** - подсказка, показываемая в пустом поле. Не является значением, не отправляется на сервер и не заменяет `<label>`.

Пример:

```html
<input
  name="username"
  value="Alex"
  placeholder="Введите имя"
>
```

Изначально значение равно `Alex`. Если пользователь изменит его на `John`, то:

- `input.value` вернёт `"John"`
- `input.defaultValue` вернёт `"Alex"`, если исходное значение не меняли программно
- При отправке формы будет использовано `"John"`

В React различие особенно важно:

- `value` вместе с `onChange` используется для контролируемого поля
- `defaultValue` задаёт начальное значение неконтролируемого поля, после чего браузер управляет его текущим значением

# Как отправляется форма через GET и POST?

Способ отправки задаётся атрибутом `method` у `<form>`.

**GET** - добавляет данные формы в query-параметры URL.

```html
<form action="/search" method="get">
  <input name="q" value="React">
  <button type="submit">Поиск</button>
</form>
```

Результат:

```text
/search?q=React
```

Особенности GET:

- Подходит для поиска, фильтрации и получения данных
- Параметры видны в URL
- URL можно сохранить в закладки
- Запросы могут кешироваться

**POST** - передаёт данные формы в теле HTTP-запроса.

```html
<form action="/login" method="post">
  <input name="email">
  <input name="password" type="password">
  <button type="submit">Войти</button>
</form>
```

По умолчанию тело кодируется как `application/x-www-form-urlencoded`.

POST обычно используется для создания или изменения данных, отправки файлов и передачи информации, которую не следует помещать в URL.

Важно: POST сам по себе не обеспечивает конфиденциальность. Защиту данных при передаче обеспечивает HTTPS.

При обычной отправке браузер выполняет навигацию к ответу сервера. Для отправки без навигации используют JavaScript и `fetch()`.

# Что делает `enctype="multipart/form-data"`?

Атрибут `enctype` определяет формат кодирования данных формы при отправке.

`multipart/form-data` разбивает тело запроса на отдельные части, каждая из которых содержит собственные заголовки и данные. Части разделяются специальной границей - `boundary`.

Это позволяет передавать текстовые поля и файлы, сохраняя их содержимое.

```html
<form
  action="/upload"
  method="post"
  enctype="multipart/form-data"
>
  <input type="file" name="avatar">
  <button type="submit">Загрузить</button>
</form>
```

Основные форматы:

- `application/x-www-form-urlencoded` - стандартное кодирование пар ключ-значение
- `multipart/form-data` - текстовые значения и файлы в отдельных частях
- `text/plain` - текстовый формат без стандартного кодирования формы, редко используется

При отправке `FormData` через `fetch()` заголовок `Content-Type` вручную устанавливать не нужно. Браузер самостоятельно добавит `multipart/form-data` и соответствующий `boundary`.

`enctype` применяется к отправке формы методом POST.

# Как браузер выполняет нативную валидацию формы?

Браузер проверяет значения полей на соответствие встроенным ограничениям HTML.

Например:

- `required` - наличие обязательного значения
- `type="email"` - корректность синтаксиса email
- `min` и `max` - допустимые границы
- `pattern` - соответствие регулярному выражению
- `minlength` и `maxlength` - ограничения длины

При обычной отправке браузер выполняет **интерактивную проверку ограничений** (Constraint Validation).

Если данные некорректны, браузер блокирует отправку, обычно выделяет проблемное поле и показывает сообщение об ошибке. Событие `submit` в этом случае не возникает.

Управлять проверкой позволяют:

- `novalidate` у `<form>` - отключает автоматическую проверку перед отправкой
- `formnovalidate` у кнопки отправки - отключает её для конкретной кнопки
- `checkValidity()` - проверяет ограничения и возвращает `true` или `false`
- `reportValidity()` - проверяет ограничения и дополнительно инициирует отображение ошибок

Важное различие:

- `form.requestSubmit()` запускает обычный механизм отправки, включая валидацию и событие `submit`
- `form.submit()` отправляет форму без нативной валидации и без события `submit`

Валидация в браузере предназначена для удобства пользователя. Сервер обязан проверять данные независимо.

# Как работают Constraint Validation API и `setCustomValidity()`?

**Constraint Validation API** - браузерный API для проверки HTML-полей и управления сообщениями об ошибках.

Основные свойства и методы:

- `validity` - объект `ValidityState` с состоянием ограничений
- `validationMessage` - текущее сообщение об ошибке
- `willValidate` - участвует ли элемент в проверке ограничений
- `checkValidity()` - проверяет корректность и возвращает boolean
- `reportValidity()` - проверяет корректность и запрашивает отображение сообщения
- `setCustomValidity(message)` - устанавливает собственную ошибку валидации

Объект `validity` содержит флаги:

- `valueMissing` - отсутствует обязательное значение
- `typeMismatch` - значение не соответствует типу
- `patternMismatch` - не соответствует `pattern`
- `rangeUnderflow` / `rangeOverflow` - выход за границы
- `stepMismatch` - нарушение шага
- `tooShort` / `tooLong` - нарушение ограничения длины
- `customError` - задана пользовательская ошибка
- `valid` - все ограничения соблюдены

Пример:

```js
const input = document.querySelector("#password");

input.addEventListener("input", () => {
  if (input.value && input.value.length < 8) {
    input.setCustomValidity("Минимум 8 символов");
  } else {
    input.setCustomValidity("");
  }
});
```

**Ключевая особенность:** непустое сообщение в `setCustomValidity()` делает поле невалидным независимо от остальных ограничений.

Чтобы сбросить пользовательскую ошибку, обязательно вызвать `setCustomValidity("")`. Иначе поле останется невалидным даже после исправления значения.

# Для чего нужны `autocomplete` и `inputmode`?

Оба атрибута улучшают взаимодействие с формами, но решают разные задачи.

**`autocomplete`** сообщает браузеру, какие данные ожидаются в поле, и позволяет использовать автозаполнение.

```html
<input
  type="email"
  name="email"
  autocomplete="email"
>
```

Распространённые значения:

- `name` - полное имя
- `email` - электронная почта
- `tel` - телефон
- `current-password` - существующий пароль
- `new-password` - новый пароль
- `one-time-code` - одноразовый код
- `street-address` - адрес

`autocomplete="off"` запрашивает отключение автозаполнения, но браузеры и менеджеры паролей могут игнорировать это указание.

**`inputmode`** подсказывает браузеру тип виртуальной клавиатуры, преимущественно на мобильных устройствах.

```html
<input
  type="text"
  inputmode="numeric"
>
```

Основные значения: `text`, `numeric`, `decimal`, `tel`, `email`, `url`, `search`, `none`.

Важно: `inputmode` не ограничивает допустимые символы и не выполняет валидацию. Он влияет преимущественно на интерфейс ввода.

# В чём различие `checked` и `selected`?

**`checked`** используется у `checkbox` и `radio` для указания выбранного состояния.

```html
<input type="checkbox" name="agree" checked>
```

**`selected`** используется у `<option>` для указания первоначально выбранного варианта списка.

```html
<select name="city">
  <option value="moscow">Москва</option>
  <option value="spb" selected>Санкт-Петербург</option>
</select>
```

В HTML оба атрибута являются булевыми: их наличие означает `true`, независимо от текстового значения атрибута.

Следует различать начальное состояние и текущее:

- `input.checked` - текущее состояние флажка или радиокнопки
- `input.defaultChecked` - состояние по умолчанию
- `option.selected` - текущее состояние варианта
- `option.defaultSelected` - состояние по умолчанию

В React для `checkbox` и `radio` используют `checked` или `defaultChecked`, а для `<select>` обычно задают `value` или `defaultValue` непосредственно на элементе `<select>`.

# Как работают `fieldset` и `legend`?

`<fieldset>` семантически объединяет связанные элементы формы, а `<legend>` задаёт название группы.

```html
<fieldset>
  <legend>Способ доставки</legend>

  <label>
    <input type="radio" name="delivery" value="courier">
    Курьер
  </label>

  <label>
    <input type="radio" name="delivery" value="pickup">
    Самовывоз
  </label>
</fieldset>
```

Это особенно важно для доступности: скринридер может озвучивать название группы вместе с названием конкретного поля.

Дополнительная возможность - атрибут `disabled` у `<fieldset>`, который отключает вложенные элементы управления формы. Исключение составляют элементы внутри первого дочернего `<legend>`.

Сам `<fieldset>` не изменяет формат данных и не создаёт отдельный объект при отправке формы.

# Зачем нужны `datalist` и `optgroup`?

**`<datalist>`** задаёт предлагаемые значения для связанного `<input>`.

```html
<input list="languages" name="language">

<datalist id="languages">
  <option value="JavaScript">
  <option value="TypeScript">
  <option value="Python">
</datalist>
```

Пользователь может выбрать предложенное значение или ввести собственное. Сам по себе `datalist` не ограничивает ввод только перечисленными вариантами.

**`<optgroup>`** группирует варианты внутри `<select>`.

```html
<select name="language">
  <optgroup label="Frontend">
    <option value="js">JavaScript</option>
    <option value="ts">TypeScript</option>
  </optgroup>

  <optgroup label="Backend">
    <option value="go">Go</option>
    <option value="python">Python</option>
  </optgroup>
</select>
```

Отличие:

- `datalist` - подсказки с возможностью произвольного ввода
- `optgroup` - группировка вариантов внутри списка с ограниченным набором значений

`optgroup` не является выбираемым вариантом и не отправляется как значение формы.

# Чем `submit`-кнопка отличается от `button`?

Различие определяется атрибутом `type`.

**`type="submit"`** запускает стандартный механизм отправки формы:

1. Браузер проверяет ограничения полей.
2. Если форма валидна, генерирует событие `submit`.
3. Если событие не отменено, отправляет данные согласно настройкам формы.

**`type="button"`** не выполняет встроенного действия. Обычно используется для обработки нажатия через JavaScript.

```html
<button type="submit">Сохранить</button>
<button type="button">Открыть подсказку</button>
```

Важная особенность: у `<button>` внутри формы тип по умолчанию - `submit`, если не задано другое поведение.

Поэтому кнопки, которые не должны отправлять форму, необходимо явно объявлять как `type="button"`.

Также существует `type="reset"`, который восстанавливает исходные значения элементов формы.

# Как обработать отправку формы без перезагрузки страницы?

Необходимо перехватить событие `submit`, отменить стандартную отправку через `preventDefault()` и самостоятельно отправить запрос.

```js
const form = document.querySelector("form");

form.addEventListener("submit", async (event) => {
  event.preventDefault();

  const formData = new FormData(form, event.submitter);

  try {
    const response = await fetch(form.action, {
      method: "POST",
      body: formData,
    });

    if (!response.ok) {
      throw new Error("Ошибка отправки");
    }

    // Обработка успешного ответа
  } catch (error) {
    // Обработка сетевой ошибки или ошибки HTTP
  }
});
```

Что происходит:

1. Пользователь отправляет форму.
2. Браузер выполняет нативную валидацию, если она не отключена.
3. Обработчик `submit` вызывает `preventDefault()`, предотвращая стандартную навигацию.
4. `FormData` собирает данные успешных элементов управления формы.
5. `fetch()` отправляет запрос асинхронно.
6. JavaScript обрабатывает ответ без полной перезагрузки страницы.

`event.submitter` позволяет включить в `FormData` имя и значение кнопки, которой отправили форму, если они заданы.

Важно: `fetch()` не отклоняет Promise при HTTP-ошибках вроде `400` или `500`. Поэтому необходимо проверять `response.ok`.

В React принцип тот же: обработчик `onSubmit` вызывает `event.preventDefault()`, после чего данные отправляются самостоятельно.

# Чем `FormData` отличается от JSON-представления формы?

**`FormData`** - браузерный объект для хранения и передачи данных формы в виде пар ключ-значение.

Особенности:

- Поддерживает строки и объекты `File`
- Допускает несколько значений с одинаковым именем
- Может создаваться непосредственно из HTML-формы
- При передаче в `fetch()` браузер кодирует содержимое как `multipart/form-data`

```js
const formData = new FormData(form);

formData.get("email");
formData.getAll("tags");
```

**JSON** - текстовый формат представления структурированных данных: объектов, массивов, строк, чисел, булевых значений и `null`.

```js
const data = {
  email: "user@example.com",
  age: 25,
};
```

Ключевые различия:

| Критерий            | `FormData`                   | JSON                            |
|---------------------|------------------------------|---------------------------------|
| Файлы               | Поддерживает `File`          | Не поддерживает напрямую        |
| Повторяющиеся ключи | Поддерживает                 | Обычно представляются массивами |
| Вложенные структуры | Требуют соглашения об именах | Поддерживаются нативно          |
| Создание из формы   | `new FormData(form)`         | Требует преобразования          |
| Формат передачи     | Обычно `multipart/form-data` | Обычно `application/json`       |

При отправке JSON нужно самостоятельно сериализовать объект через `JSON.stringify()` и указать `Content-Type: application/json`.

`FormData` не преобразуется в JSON автоматически. Например, `JSON.stringify(formData)` не сериализует содержащиеся пары.

`Object.fromEntries(formData)` позволяет получить простой объект, но теряет повторяющиеся ключи и не обеспечивает корректную JSON-сериализацию файлов.

# Как реализовать доступное сообщение об ошибке поля?

Ошибка должна быть не только визуально заметной, но и доступной для вспомогательных технологий.

Основные требования:

- Связать сообщение с полем через `aria-describedby`
- Установить `aria-invalid="true"` при наличии ошибки
- Использовать `role="alert"` или подходящий `aria-live` для озвучивания динамически появляющейся ошибки
- Не полагаться исключительно на цвет: добавить понятный текст ошибки
- Сохранить корректную связь поля с `<label>`

Пример:

```html
<label for="email">Email</label>

<input
  id="email"
  name="email"
  type="email"
  aria-invalid="true"
  aria-describedby="email-error"
>

<span id="email-error" role="alert">
  Введите корректный email
</span>
```

Здесь:

- `label` задаёт доступное имя поля
- `aria-invalid` сообщает, что значение некорректно
- `aria-describedby` связывает поле с текстом ошибки
- `role="alert"` позволяет скринридеру объявить ошибку при её динамическом появлении

После исправления значения нужно убрать ошибку и изменить `aria-invalid` на `false` либо удалить атрибут.

При отправке формы с несколькими ошибками полезно перевести фокус на первое невалидное поле или сводку ошибок, чтобы пользователь мог быстро найти проблему.

**Важно:** `aria-invalid` и `aria-describedby` не выполняют валидацию сами по себе. Они только передают информацию о состоянии поля вспомогательным технологиям.
