# Как превратить дерево в плоский список и наоборот?

Дерево в плоский список преобразуют обходом DFS или BFS. Каждый узел добавляют в массив, сохраняя `id` и `parentId`, чтобы не потерять иерархию.

Плоский список в дерево преобразуют за два прохода:

1. Создают `Map<id, node>`, где каждый узел содержит пустой массив `children`.
2. Для каждого узла находят родителя по `parentId` и добавляют узел в его `children`. Узлы без родителя становятся корневыми.

Сложность: `O(n)` по времени и памяти при использовании `Map`.

Важно учитывать отсутствующих родителей, дублирующиеся `id` и циклические связи. Если порядок дочерних узлов имеет значение, его также нужно сохранять.

# Как оценивать асимптотическую сложность времени и памяти?

Асимптотическая сложность показывает, как растут затраты алгоритма при увеличении размера входных данных `n`.

Временная сложность оценивает количество операций, а пространственная - объём дополнительной памяти, включая вспомогательные структуры и стек вызовов.

Основные классы сложности:

- `O(1)` - константная: доступ к элементу массива по индексу.
- `O(log n)` - логарифмическая: бинарный поиск.
- `O(n)` - линейная: один проход по массиву.
- `O(n log n)` - линейно-логарифмическая: merge sort.
- `O(n²)` - квадратичная: два вложенных цикла по `n` элементов.
- `O(2^n)` - экспоненциальная: полный перебор подмножеств.

При анализе:

1. Определяют размер входных данных.
2. Подсчитывают количество операций с учётом циклов, рекурсии и вызовов других алгоритмов.
3. Отбрасывают константы и младшие члены: `O(3n² + 5n)` превращается в `O(n²)`.
4. Отдельно оценивают дополнительную память.

Последовательные операции складываются, вложенные циклы обычно перемножают количество итераций.

Для рекурсивных алгоритмов учитывают количество вызовов и глубину стека. Например, рекурсивный DFS дерева занимает `O(h)` дополнительной памяти, где `h` - высота дерева.

Обычно рассматривают худший случай, но при необходимости отдельно оценивают среднюю и амортизированную сложность.

# Чем массив отличается от связного списка?

Массив предоставляет доступ к элементам по индексам. Связный список состоит из узлов, каждый из которых содержит значение и ссылку на следующий узел, а в двусвязном списке - также на предыдущий.

| Операция                 | Динамический массив    | Связный список                        |
|--------------------------|------------------------|---------------------------------------|
| Доступ по индексу        | `O(1)`                 | `O(n)`                                |
| Поиск значения           | `O(n)`                 | `O(n)`                                |
| Вставка в начало         | `O(n)`                 | `O(1)`                                |
| Вставка в конец          | `O(1)` амортизированно | `O(1)` при наличии `tail`             |
| Удаление известного узла | `O(n)` из-за сдвига    | `O(1)` при наличии необходимых ссылок |

Массивы обычно обеспечивают лучшую локальность данных в памяти и эффективнее используют процессорный кеш.

Связные списки требуют дополнительной памяти для ссылок и удобны, когда необходимо часто вставлять или удалять уже найденные узлы.

В JavaScript `Array` - динамический массив на уровне API, но движок не гарантирует непрерывное размещение элементов в памяти.

# Когда использовать `Map` и `Set` для решения задач?

`Map` хранит пары ключ-значение. `Set` хранит уникальные значения.

Обе структуры используют, когда требуется быстрый поиск, добавление или удаление элементов - в среднем `O(1)` на операцию.

`Map` подходит для:

- Подсчёта частот: `Map<символ, количество>`.
- Индексации объектов по идентификатору.
- Кеширования результатов вычислений.
- Хранения связей между элементами.

`Set` подходит для:

- Удаления дубликатов.
- Проверки существования элемента.
- Хранения посещённых вершин графа.
- Поиска пересечений и объединений множеств.

В отличие от обычного объекта, `Map` поддерживает ключи любых типов, включая объекты. При этом объектные ключи сравниваются по ссылочной идентичности.

`Map` и `Set` сохраняют порядок добавления элементов, но не сортируют их.

Ограничение: быстрые операции достигаются ценой дополнительной памяти, обычно `O(n)`.

# Как реализовать стек и очередь?

Стек (LIFO) работает по принципу «последним пришёл - первым вышел».

В JavaScript его удобно реализовать через массив:

```
const stack = [];

stack.push(1);
stack.push(2);

stack.pop(); // 2
```

Операции `push` и `pop` имеют амортизированную сложность `O(1)`.

Стек используется в DFS, обработке вложенных конструкций, отмене действий и вычислении выражений.

Очередь (FIFO) работает по принципу «первым пришёл - первым вышел».

Для простой эффективной реализации можно использовать массив и индекс начала:

```
const queue = [];
let head = 0;

queue.push(1);
queue.push(2);

const first = queue[head++]; // 1
```

Чтение через `head` занимает `O(1)`, но обработанные элементы продолжают занимать память. Поэтому при длительной работе массив нужно периодически очищать или использовать кольцевой буфер.

Метод `Array.shift()` обычно имеет сложность `O(n)`, поскольку может сдвигать оставшиеся элементы.

Очереди применяются в BFS, планировщиках задач и обработке событий.

# Что такое двоичный поиск и какие предпосылки он требует?

Двоичный поиск (binary search) - алгоритм, который на каждом шаге сокращает область поиска примерно вдвое.

Для поиска значения в отсортированном массиве:

1. Определяют левую и правую границы.
2. Находят средний элемент.
3. Сравнивают его с искомым значением.
4. Отбрасывают половину массива, в которой значение не может находиться.
5. Повторяют до нахождения элемента или исчерпания диапазона.

Сложность: `O(log n)` по времени и `O(1)` по дополнительной памяти для итеративной реализации.

Основное условие - монотонность условия поиска. Для классического поиска значения массив должен быть отсортирован по соответствующему критерию.

Бинарный поиск также применяется для поиска границ, например первого элемента `>= target`, и минимального значения, удовлетворяющего монотонному предикату.

При наличии дубликатов обычный бинарный поиск не гарантирует нахождение первого или последнего вхождения. Для этого используются варианты `lower_bound` и `upper_bound`.

# Как работают two pointers и sliding window?

Two pointers (два указателя) - техника, в которой два индекса перемещаются по структуре данных, сокращая количество проверок.

Типичные варианты:

- Указатели с противоположных концов отсортированного массива для поиска пары с заданной суммой.
- Два указателя, движущиеся в одном направлении, для обработки диапазонов.
- Медленный и быстрый указатели для обнаружения цикла в связном списке.

Sliding window (скользящее окно) - частный случай техники двух указателей, где поддерживается текущий непрерывный диапазон `[left, right]`.

При расширении или сужении окна алгоритм обновляет его состояние без повторного пересчёта всех элементов.

Например, при поиске максимальной суммы подмассива длины `k` достаточно вычитать элемент, выходящий из окна, и добавлять входящий.

Сложность: часто `O(n)`, если каждый указатель проходит массив не более одного раза.

Ограничение: алгоритм расширения и сужения окна требует подходящего свойства монотонности. Например, поиск минимального подмассива с суммой не меньше `target` стандартным sliding window корректен для неотрицательных чисел, но не работает в общем случае с отрицательными.

# Когда нужен prefix sum?

Prefix sum (префиксные суммы) используют для быстрого вычисления суммы элементов на произвольном диапазоне массива.

Строится массив:

\\[ P[0]=0,\qquad P[i+1]=P[i]+A[i] \\]

Тогда сумма элементов на полуинтервале `[l, r)`:

\\[ sum(l,r)=P[r]-P[l] \\]

Сложность:

- Предварительное построение - `O(n)`.
- Запрос суммы диапазона - `O(1)`.
- Дополнительная память - `O(n)`.

Префиксные суммы особенно полезны, когда массив не изменяется, но требуется выполнять много запросов суммы.

Также их используют для поиска подмассивов с заданной суммой. Например, если `P[j] - P[i] = k`, то сумма подмассива `[i, j)` равна `k`. С помощью `Map` частот префиксных сумм такие задачи можно решать за `O(n)`, в том числе при наличии отрицательных чисел.

Ограничение: при изменении элемента массива необходимо обновлять последующие префиксные суммы. Для частых изменений и запросов эффективнее дерево Фенвика или дерево отрезков.

# Как обнаружить цикл в графе?

Способ зависит от того, ориентированный граф или неориентированный.

В неориентированном графе используют DFS с запоминанием родительской вершины. Если обнаружено ребро к уже посещённой вершине, которая не является родителем текущей, найден цикл.

В ориентированном графе применяют DFS с тремя состояниями вершин:

- `WHITE` - ещё не посещена.
- `GRAY` - находится в текущем стеке обхода.
- `BLACK` - полностью обработана.

Если из текущей вершины существует ребро к `GRAY`, обнаружен цикл.

Другой способ - алгоритм Кана: последовательно удаляют вершины с нулевой входящей степенью. Если после обработки остаются вершины, граф содержит цикл.

Для неориентированных графов также подходит DSU (Disjoint Set Union): если концы очередного ребра уже принадлежат одному множеству, добавление этого ребра образует цикл.

Сложность DFS и алгоритма Кана: `O(V + E)` по времени, где `V` - количество вершин, `E` - количество рёбер.

# Чем DFS отличается от BFS?

DFS (Depth-First Search) обходит граф в глубину, сначала исследуя одну ветвь до конца, затем возвращаясь назад.

Реализуется рекурсией или явным стеком.

Используется для обнаружения циклов, топологической сортировки, поиска компонент связности и обхода деревьев.

BFS (Breadth-First Search) обходит граф в ширину, последовательно исследуя вершины на одинаковом расстоянии от стартовой.

Реализуется через очередь.

Используется для поиска кратчайшего пути в невзвешенном графе и определения минимального количества переходов между вершинами.

| Характеристика                   | DFS            | BFS         |
|----------------------------------|----------------|-------------|
| Структура данных                 | Стек           | Очередь     |
| Порядок обхода                   | В глубину      | По уровням  |
| Кратчайший путь без весов        | Не гарантирует | Гарантирует |
| Дополнительная память для дерева | `O(h)`         | `O(w)`      |

Здесь `h` - высота дерева, `w` - максимальная ширина уровня.

Для графов: оба алгоритма имеют временную сложность `O(V + E)` при использовании списков смежности. С учётом хранения посещённых вершин дополнительная память в худшем случае составляет `O(V)`.

# Как построить дерево из плоского массива с `parentId`?

Оптимальный подход - использовать `Map` для быстрого поиска родителей по идентификатору.

Алгоритм:

1. Создать копии всех узлов с пустым массивом `children`.
2. Сохранить узлы в `Map`, где ключ - `id`.
3. Пройти по узлам: если `parentId === null`, добавить узел в корни, иначе найти родителя и добавить узел в `parent.children`.

```
function buildTree(items) {
  const nodes = new Map(
    items.map(item => [
      item.id,
      { ...item, children: [] }
    ])
  );

  const roots = [];

  for (const node of nodes.values()) {
    if (node.parentId == null) {
      roots.push(node);
    } else {
      const parent = nodes.get(node.parentId);

      if (!parent) {
        throw new Error("Parent not found");
      }

      parent.children.push(node);
    }
  }

  return roots;
}
```

Сложность: `O(n)` по времени и памяти.

Метод работает независимо от порядка элементов во входном массиве.

Важно проверять уникальность `id`, существование родителей и отсутствие циклов. Приведённая реализация проверяет только существование родителей.

# Как обойти дерево в глубину и ширину?

Существуют два основных способа обхода дерева.

DFS (обход в глубину) последовательно исследует дочерние узлы, прежде чем переходить к соседним ветвям.

Реализуется рекурсией или стеком.

Основные варианты DFS:

- Preorder - обработка узла перед дочерними узлами.
- Postorder - обработка узла после дочерних.
- Inorder - для бинарного дерева: левое поддерево, узел, правое поддерево.

DFS применяют для поиска элементов, обработки вложенных структур и вычисления агрегатов поддеревьев.

BFS (обход в ширину) посещает узлы по уровням: сначала корень, затем его детей, затем внуков.

Реализуется очередью. При обработке узла его детей добавляют в конец очереди.

Сложность:

- Время обоих обходов - `O(n)`.
- Память рекурсивного DFS - `O(h)`, где `h` - высота дерева.
- Память BFS - `O(w)`, где `w` - максимальная ширина уровня.

DFS удобнее для рекурсивной обработки иерархии, BFS - для поиска ближайшего узла и обработки дерева по уровням.

# Как найти общий предок двух узлов дерева?

LCA (Lowest Common Ancestor) - самый глубокий узел дерева, являющийся предком двух заданных узлов. Узел обычно считается предком самого себя.

Если у каждого узла есть ссылка `parent`, можно:

1. Подняться от первого узла к корню, сохраняя предков в `Set`.
2. Подниматься от второго узла, пока не встретится узел из `Set`.
3. Первый найденный общий узел будет LCA.

Сложность: `O(h)` по времени и памяти, где `h` - высота дерева.

Если известны глубины узлов, можно обойтись без `Set`: сначала поднять более глубокий узел до уровня второго, затем поднимать оба одновременно до совпадения. Это занимает `O(h)` времени и `O(1)` дополнительной памяти.

Если ссылок на родителей нет, можно выполнить DFS от корня и найти пути к обоим узлам. Последний совпадающий элемент этих путей - LCA. Время - `O(n)`.

Для большого количества запросов LCA используют binary lifting - предварительно вычисляют предков каждого узла на расстояниях `2^k`.

- Предобработка - `O(n log n)`.
- Один запрос - `O(log n)`.

# Что такое topological sort и где он полезен в графе зависимостей?

Топологическая сортировка - упорядочивание вершин ориентированного графа так, чтобы для каждого ребра `A -> B` вершина `A` находилась раньше `B`.

Применяется только к ориентированным ациклическим графам (DAG).

Основные алгоритмы:

1\. Алгоритм Кана (Kahn's algorithm)

- Вычисляет входящую степень каждой вершины.
- Добавляет в очередь вершины с нулевой входящей степенью.
- Извлекает вершину, добавляет в результат и уменьшает входящие степени её соседей.
- Повторяет до опустошения очереди.

Если обработаны не все вершины, граф содержит цикл.

2\. DFS

Выполняет обход в глубину и добавляет вершины в результат после обработки всех исходящих рёбер. Затем разворачивает полученный порядок. Циклы необходимо обнаруживать отдельно.

Сложность: `O(V + E)` по времени и `O(V)` дополнительной памяти, не считая хранения графа.

Применяется для определения порядка сборки модулей, выполнения задач с зависимостями, запуска миграций и установки пакетов.

Топологический порядок может быть неединственным.

# Чем heap отличается от отсортированного массива?

Heap (куча) - структура данных, обычно реализованная в виде массива, которая поддерживает свойство кучи:

- Min-heap: родитель не больше своих дочерних элементов.
- Max-heap: родитель не меньше своих дочерних элементов.

Куча не хранит все элементы в отсортированном порядке. Она гарантирует только, что минимальный или максимальный элемент находится в корне.

| Операция                              | Heap       | Отсортированный массив                    |
|---------------------------------------|------------|-------------------------------------------|
| Получение минимума                    | `O(1)`     | `O(1)`                                    |
| Вставка                               | `O(log n)` | `O(n)`                                    |
| Удаление минимума                     | `O(log n)` | `O(n)`                                    |
| Поиск произвольного значения          | `O(n)`     | `O(log n)`                                |
| Построение структуры из `n` элементов | `O(n)`     | `O(n log n)` при сравнительной сортировке |

Для массива предполагается хранение по возрастанию. Удаление минимума требует сдвига элементов.

Heap используют, когда нужно постоянно добавлять элементы и извлекать минимальный или максимальный: очереди с приоритетами, планировщики, алгоритм Дейкстры, поиск `k` наибольших элементов.

Отсортированный массив удобнее, когда данные редко изменяются, но требуется быстрый поиск произвольных значений.

# Как реализовать LRU cache?

LRU (Least Recently Used) - кеш, который при достижении лимита удаляет элемент, использовавшийся раньше остальных.

Классическая реализация объединяет:

- `HashMap` для поиска элементов за `O(1)` в среднем.
- Двусвязный список для отслеживания порядка использования и перемещения узлов за `O(1)`.

При `get` или обновлении существующего элемента его перемещают в начало списка. При переполнении удаляют последний элемент.

В JavaScript можно использовать `Map`, поскольку он сохраняет порядок вставки.

```
class LRUCache {
  constructor(capacity) {
    if (capacity < 1) {
      throw new Error("Invalid capacity");
    }

    this.capacity = capacity;
    this.cache = new Map();
  }

  get(key) {
    if (!this.cache.has(key)) {
      return undefined;
    }

    const value = this.cache.get(key);

    this.cache.delete(key);
    this.cache.set(key, value);

    return value;
  }

  put(key, value) {
    this.cache.delete(key);
    this.cache.set(key, value);

    if (this.cache.size > this.capacity) {
      const oldest = this.cache.keys().next().value;
      this.cache.delete(oldest);
    }
  }
}
```

Удаление и повторная вставка обновляют позицию ключа в порядке обхода `Map`.

Сложность: `O(1)` в среднем для `get` и `put`, `O(capacity)` по памяти.

Важно, что `get` тоже обновляет порядок использования. Если кеш допускает хранение `undefined`, API должен отдельно различать отсутствие ключа и сохранённое значение `undefined`.

# Что такое dynamic programming и memoization?

Dynamic Programming (динамическое программирование) - метод решения задач через разбиение на повторяющиеся подзадачи с сохранением промежуточных результатов.

Обычно применяется, когда задача обладает двумя свойствами:

- Перекрывающиеся подзадачи: одни и те же состояния вычисляются многократно.
- Оптимальная подструктура: решение исходной задачи можно получить из решений меньших подзадач.

Два основных подхода:

Memoization (мемоизация) - рекурсивное решение сверху вниз (`top-down`) с кешированием результатов. Состояние вычисляется только при первом обращении.

Tabulation (табуляция) - итеративное решение снизу вверх (`bottom-up`). Результаты вычисляют в порядке зависимостей и сохраняют в таблице.

Пример - числа Фибоначчи:

\\[ F(n)=F(n-1)+F(n-2) \\]

Наивная рекурсия многократно пересчитывает одинаковые значения, поэтому имеет экспоненциальную временную сложность.

С мемоизацией каждое значение `F(n)` вычисляется один раз:

- Время - `O(n)`.
- Память - `O(n)`.

При итеративном вычислении достаточно хранить два последних значения, поэтому память сокращается до `O(1)`.

Главное в динамическом программировании - правильно определить состояние, переход между состояниями и базовые случаи.

# Как искать подстроку и считать частоты символов?

Поиск подстроки - определение позиции, с которой заданная последовательность символов встречается в строке.

В JavaScript используют:

- `includes()` - проверка наличия подстроки.
- `indexOf()` - поиск позиции первого вхождения.
- `lastIndexOf()` - поиск позиции последнего вхождения.

При наивном поиске каждую возможную позицию проверяют посимвольно. В худшем случае сложность составляет `O(n * m)`, где `n` - длина строки, `m` - длина подстроки.

Для гарантированного линейного поиска используют KMP (Knuth-Morris-Pratt). Алгоритм предварительно вычисляет префиксную функцию шаблона, позволяющую после несовпадения не проверять повторно уже известные совпадающие части.

Сложность KMP - `O(n + m)`.

Подсчёт частот символов выполняют с помощью `Map`:

```
function countChars(str) {
  const freq = new Map();

  for (const char of str) {
    freq.set(char, (freq.get(char) ?? 0) + 1);
  }

  return freq;
}
```

Сложность: `O(n)` по времени и `O(k)` по памяти, где `k` - количество различных символов.

Важно учитывать Unicode: JavaScript хранит строки в UTF-16, а `for...of` перебирает Unicode-кодовые точки. Один визуально воспринимаемый символ может состоять из нескольких кодовых точек. Для подсчёта таких символов можно использовать `Intl.Segmenter`.

# Как найти пересечение двух больших наборов идентификаторов?

Пересечение множеств - идентификаторы, присутствующие одновременно в обоих наборах.

Основные способы:

1\. Через `Set`

- Добавить элементы меньшего набора в `Set`.
- Пройти по большему набору.
- Проверять наличие каждого элемента через `has()`.

Ожидаемая сложность - `O(n + m)` по времени и `O(min(n, m))` дополнительной памяти, без учёта результата.

Если нужны только уникальные идентификаторы, результат также следует формировать через `Set` или удалять уже найденные значения из исходного `Set`.

2\. Через two pointers

Если оба набора отсортированы:

- Установить указатели в начало.
- Если элементы равны - добавить значение в результат и сдвинуть указатели.
- Если различаются - сдвинуть указатель с меньшим значением.

Сложность - `O(n + m)` по времени и `O(1)` дополнительной памяти, без учёта результата.

При необходимости исключать дубликаты одинаковые соседние значения пропускают.

Для очень больших данных, не помещающихся в память, используют внешнюю сортировку, потоковый merge join или операции соединения в базе данных.

Выбор зависит от отсортированности данных, доступной памяти и необходимости сохранять уникальность результата.

# Как проверить корректность скобочной последовательности?

Для проверки последовательности с разными типами скобок используют стек.

Алгоритм:

1. При открывающей скобке `(`, `[` или `{` добавить её в стек.
2. При закрывающей проверить, соответствует ли она последней открывающей.
3. Если стек пуст или типы не совпадают - последовательность некорректна.
4. После обхода стек должен быть пустым.

```
function isValid(str) {
  const stack = [];
  const pairs = {
    ")": "(",
    "]": "[",
    "}": "{"
  };

  for (const char of str) {
    if ("([{".includes(char)) {
      stack.push(char);
    } else if (char in pairs) {
      if (stack.pop() !== pairs[char]) {
        return false;
      }
    }
  }

  return stack.length === 0;
}
```

Сложность:

- Время - `O(n)`.
- Дополнительная память - `O(n)` в худшем случае.

Если существует только один тип скобок, достаточно одного счётчика: увеличивать при открытии и уменьшать при закрытии. Счётчик никогда не должен становиться отрицательным, а в конце обязан равняться нулю. Память в таком случае - `O(1)`.

# Как реализовать debounce и throttle с заданными требованиями?

Debounce откладывает выполнение функции, пока события продолжают поступать. При каждом новом вызове таймер перезапускается.

Например, поиск запускается через 300 мс после последнего ввода символа.

Throttle ограничивает частоту выполнения функции: не чаще одного раза за заданный интервал.

Например, обработчик `scroll` выполняется не чаще одного раза за 100 мс.

Простая реализация `debounce` с выполнением после последнего вызова (`trailing`):

```
function debounce(fn, delay) {
  let timer;

  return function (...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      timer = undefined;
      fn.apply(this, args);
    }, delay);
  };
}
```

При каждом вызове предыдущий таймер отменяется. Функция выполнится только после периода без новых вызовов.

Реализация `throttle` с немедленным первым выполнением (`leading`) без отложенного последнего вызова:

```
function throttle(fn, interval) {
  let blocked = false;

  return function (...args) {
    if (blocked) return;

    blocked = true;

    setTimeout(() => {
      blocked = false;
    }, interval);

    fn.apply(this, args);
  };
}
```

После первого выполнения новые вызовы игнорируются до завершения интервала.

При реализации по требованиям необходимо определить:

- `leading` - выполнять ли функцию сразу при первом вызове.
- `trailing` - выполнять ли последний отложенный вызов.
- `maxWait` - максимальное время ожидания выполнения при непрерывных событиях.
- `cancel()` - возможность отменить ожидающее выполнение.
- `flush()` - возможность немедленно выполнить ожидающий вызов.
- Сохранение `this`, актуальных аргументов и корректное поведение при повторных вызовах.

Приведённые реализации поддерживают только указанные базовые режимы. Для комбинаций `leading`, `trailing` и `maxWait` необходима дополнительная логика управления временем и отложенными вызовами.

Оба механизма обычно имеют `O(1)` затрат на обработку события и `O(1)` дополнительной памяти. Реальное время срабатывания таймеров зависит от event loop и не гарантируется с абсолютной точностью.
