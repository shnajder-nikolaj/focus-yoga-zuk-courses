# Чем `var`, `let` и `const` отличаются друг от друга?

Основные различия - область видимости, возможность повторного объявления, переназначения и поведение при hoisting.

- `var` - функциональная область видимости, допускает повторное объявление и переназначение. Поднимается с инициализацией `undefined`.
- `let` - блочная область видимости, допускает переназначение, но запрещает повторное объявление в одной области. До инициализации находится в Temporal Dead Zone (TDZ).
- `const` - аналогичен `let`, но запрещает переназначение и требует инициализации при обычном объявлении.

`const` не делает объект неизменяемым - запрещено только переназначение самой переменной. Свойства объекта можно изменять.

На практике используют `const` по умолчанию, `let` - когда требуется переназначение. `var` преимущественно встречается в устаревшем коде.

# Что такое lexical scope?

Lexical scope (лексическая область видимости) - механизм, при котором доступность переменных определяется местом написания кода, а не местом вызова функции.

Функция имеет доступ к переменным собственной и внешних лексических областей, в которых она была объявлена.

```
const value = 10;

function outer() {
  const value = 20;

  return function inner() {
    return value;
  };
}

const fn = outer();
fn(); // 20
```

`inner` обращается к `value` из `outer`, даже когда вызывается за пределами этой функции. Это основа работы замыканий.

# Как работает hoisting?

Hoisting (поднятие) - поведение JavaScript, при котором объявления регистрируются при создании контекста выполнения, до непосредственного выполнения кода.

Поведение зависит от типа объявления:

- `var` - создаётся и инициализируется значением `undefined`, поэтому доступен до строки объявления.
- `let` и `const` - создаются, но остаются неинициализированными до выполнения объявления. Обращение раньше вызывает `ReferenceError`.
- Function Declaration - обычно полностью инициализируется функцией до выполнения кода, поэтому может вызываться до объявления.
- Function Expression - подчиняется правилам переменной, которой присваивается функция.

```
console.log(a); // undefined
var a = 10;

console.log(b); // ReferenceError
let b = 20;

sayHello(); // Работает

function sayHello() {
  console.log("Hello");
}
```

Важно: JavaScript физически не перемещает объявления вверх файла. Hoisting - следствие создания привязок переменных и функций перед выполнением кода.

# Что такое temporal dead zone?

Temporal Dead Zone (TDZ) - период от начала лексической области видимости до инициализации переменной, объявленной через `let`, `const` или `class`.

В этот период привязка уже существует, но любое обращение к её значению вызывает `ReferenceError`, включая `typeof`.

```
const value = 10;

{
  console.log(value); // ReferenceError
  let value = 20;
}
```

Внутренняя переменная `value` затеняет внешнюю на протяжении всего блока, даже до своей инициализации.

TDZ предотвращает использование переменных до их корректной инициализации.

# Как устроена цепочка областей видимости?

Scope Chain - цепочка связанных лексических окружений, по которой JavaScript ищет идентификаторы.

При обращении к переменной движок:

1. Проверяет текущую область видимости.
2. Если переменная не найдена, переходит во внешнюю область.
3. Продолжает поиск до глобальной области.
4. Если привязка не найдена, возникает `ReferenceError` при чтении.

```
const a = 1;

function outer() {
  const b = 2;

  function inner() {
    const c = 3;
    console.log(a, b, c);
  }

  inner();
}
```

`inner` имеет доступ к `c`, `b` и `a`. При этом `outer` не имеет доступа к `c`.

Цепочка формируется лексически - по вложенности кода, а не по последовательности вызовов функций.

Если одинаковые имена встречаются в нескольких областях, используется ближайшая привязка. Это называется shadowing (затенение).

# Чем function declaration отличается от function expression?

Function Declaration - объявление функции отдельной инструкцией.

```
sayHello(); // Работает

function sayHello() {
  return "Hello";
}
```

Function Expression - функциональное выражение, результат которого можно присвоить переменной или передать как значение.

```
const sayHello = function () {
  return "Hello";
};
```

Основные отличия:

- Function Declaration обычно доступна до места объявления благодаря hoisting.
- Function Expression становится доступной по правилам переменной, в которой хранится.
- Function Expression может быть анонимной или именованной.
- Function Declaration используется для самостоятельных объявлений, Function Expression - когда функция нужна как значение выражения.

Оба варианта создают обычные функции с собственным `this` и `arguments` при вызове.

# Чем стрелочная функция отличается от обычной?

Стрелочная функция (`=>`) - сокращённый синтаксис функции с лексическим `this` и рядом особенностей.

Основные отличия:

- `this` - стрелочная функция использует значение из окружающего лексического контекста, обычная определяет его способом вызова.
- `arguments` - стрелочная функция не имеет собственного объекта `arguments`.
- Конструктор - стрелочную функцию нельзя вызвать через `new`; у неё нет собственного `prototype` для конструирования.
- `super` и `new.target` - стрелочная функция не создаёт собственные привязки для них.
- Генераторы - стрелочные функции не могут быть генераторами и использовать `yield` как оператор генератора.
- Возврат значения - стрелочная функция позволяет не писать `return` для выражения без фигурных скобок.

```
const double = x => x * 2;
```

Стрелочные функции удобны для колбэков и случаев, когда нужно сохранить внешний `this`. Обычные функции подходят для методов с динамическим `this` и конструкторов.

# Как определяется `this` у обычной функции?

У обычной функции `this` определяется способом вызова, а не местом объявления.

Основные правила:

- Вызов как метода: `obj.method()` - `this` указывает на `obj`.
- Обычный вызов: `fn()` - `this` равен `undefined` в строгом режиме; в нестрогом режиме обычно используется `globalThis`.
- Явная привязка: `call`, `apply`, `bind` позволяют задать `this`.
- Вызов через `new`: создаётся новый объект, который становится `this` конструктора.

```
function showName() {
  return this.name;
}

const user = {
  name: "Alex",
  showName,
};

user.showName(); // "Alex"

const fn = user.showName;
fn(); // TypeError в строгом режиме
```

При извлечении метода в отдельную переменную связь с объектом теряется. Поэтому `this` часто привязывают через `bind` или используют стрелочную функцию-обёртку.

# Почему стрелочная функция не имеет собственного `this`?

Стрелочные функции специально спроектированы с лексическим `this`, чтобы сохранять контекст окружающего кода.

В отличие от обычных функций, при вызове стрелочной функции новое значение `this` не устанавливается. Оно берётся из внешнего окружения.

```
const user = {
  name: "Alex",

  greet() {
    const getName = () => this.name;

    return getName();
  },
};

user.greet(); // "Alex"
```

`getName` использует `this` метода `greet`, который был вызван через `user`.

`call`, `apply` и `bind` не могут изменить `this` стрелочной функции. Поэтому стрелочную функцию обычно не используют как метод объекта, если требуется получать `this` из объекта при вызове.

# Для чего нужны `call`, `apply` и `bind`?

Эти методы `Function.prototype` позволяют явно управлять значением `this` обычной функции.

- `call(thisArg, ...args)` - немедленно вызывает функцию, передавая аргументы по отдельности.
- `apply(thisArg, args)` - немедленно вызывает функцию, передавая аргументы в массиве или массивоподобном объекте.
- `bind(thisArg, ...args)` - возвращает новую функцию с привязанным `this` и, при необходимости, начальными аргументами. Сразу её не вызывает.

```
function greet(greeting) {
  return `${greeting}, ${this.name}`;
}

const user = { name: "Alex" };

greet.call(user, "Hi");
greet.apply(user, ["Hi"]);

const bound = greet.bind(user);
bound("Hi");
```

В современном коде вместо `apply` для массивов аргументов часто используют spread: `fn(...args)`.

Для стрелочных функций переданное значение `thisArg` не меняет их лексический `this`.

# Как устроены `arguments` и rest parameters?

`arguments` - массивоподобный объект, доступный внутри обычных функций и содержащий переданные при вызове аргументы.

Он имеет индексы и `length`, но не является настоящим массивом и не обладает всеми методами `Array.prototype`.

Rest parameters (`...args`) - синтаксис сбора оставшихся аргументов в настоящий массив.

```
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3); // 6
```

Основные различия:

- `arguments` содержит все переданные аргументы, rest - только аргументы, оставшиеся после явно объявленных параметров.
- Rest создаёт массив, с которым напрямую работают `map`, `filter`, `reduce`.
- Стрелочные функции не имеют собственного `arguments`, но поддерживают rest parameters.
- Rest-параметр должен быть последним в списке параметров.

В современном JavaScript предпочтительнее rest parameters из-за явного синтаксиса и полноценной работы с массивами.

# Что такое IIFE и где этот паттерн использовали?

IIFE (Immediately Invoked Function Expression) - функциональное выражение, которое вызывается сразу после создания.

```
(function () {
  const secret = "private";
  console.log(secret);
})();
```

Основные применения:

- Создание отдельной области видимости, чтобы не загрязнять глобальную.
- Инкапсуляция приватных переменных через замыкания.
- Реализация модулей до появления ES Modules.
- Изоляция переменных в старом коде с `var`, у которого нет блочной области видимости.

С появлением `let`, `const` и ES Modules необходимость в IIFE значительно снизилась.

Однако асинхронные IIFE всё ещё встречаются, например для немедленного запуска `async`-функции в контексте без top-level await.

# Что такое функция высшего порядка?

Функция высшего порядка (Higher-Order Function) - функция, которая принимает другую функцию как аргумент и/или возвращает функцию.

```
const numbers = [1, 2, 3];

const doubled = numbers.map(x => x * 2);
```

Здесь `map` - функция высшего порядка, поскольку принимает колбэк.

Такие функции позволяют абстрагировать общую логику и передавать поведение в виде функции.

Применяются в `map`, `filter`, `reduce`, обработчиках событий, декораторах, мемоизации и функциональном программировании.

# Что означает, что функции являются объектами первого класса?

First-class functions означает, что JavaScript позволяет работать с функциями как с обычными значениями.

Функции можно:

- Присваивать переменным и свойствам объектов.
- Передавать аргументами другим функциям.
- Возвращать из функций.
- Хранить в массивах и других структурах данных.

```
function createMultiplier(n) {
  return x => x * n;
}

const double = createMultiplier(2);

double(5); // 10
```

При этом функции в JavaScript являются объектами: могут иметь свойства, передаваться по ссылке на объект и вызываться благодаря внутренней способности к вызову `[[Call]]`.

Это фундамент для колбэков, замыканий и функций высшего порядка.

# Что такое замыкание и какие данные оно удерживает?

Замыкание (Closure) - функция вместе с доступом к лексическому окружению, в котором она была создана.

Благодаря этому функция может обращаться к переменным внешней функции даже после завершения её выполнения.

```
function createCounter() {
  let count = 0;

  return () => ++count;
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

Замыкание сохраняет доступ к привязкам переменных, а не к копиям их значений. Поэтому изменения переменных видны при последующих вызовах.

Внешнее окружение может продолжать существовать, пока оно доступно через замыкание. При этом движок может оптимизировать хранение и не сохранять переменные, которые больше не нужны.

Замыкания используются для приватного состояния, фабрик функций, обработчиков событий, мемоизации и асинхронных операций.

# Как реализовать счётчик с приватным состоянием через замыкание?

```
function createCounter() {
  let count = 0;

  return {
    increment() {
      return ++count;
    },

    decrement() {
      return --count;
    },

    getValue() {
      return count;
    },
  };
}

const counter = createCounter();

counter.increment(); // 1
counter.increment(); // 2
counter.getValue();  // 2
counter.decrement(); // 1
```

Переменная `count` находится в лексическом окружении `createCounter` и недоступна напрямую извне.

Возвращаемые методы образуют замыкания и разделяют доступ к одному состоянию.

Каждый вызов `createCounter()` создаёт новое независимое состояние.

# Как замыкания могут приводить к утечкам памяти?

Замыкания сохраняют доступ к внешнему лексическому окружению. Пока замыкание достижимо, связанные с ним данные, необходимые для работы функции, могут оставаться в памяти.

Проблемы возникают, когда долгоживущие замыкания удерживают большие объекты или DOM-узлы, которые больше не используются.

```
function setup() {
  const data = new Array(1_000_000).fill("data");

  const handler = () => {
    console.log(data.length);
  };

  window.addEventListener("resize", handler);
}
```

Пока обработчик зарегистрирован, он остаётся достижимым через `window` и удерживает `data`.

Это не утечка в смысле потери контроля над памятью, но может быть нежелательным удержанием памяти.

Типичные причины - забытые обработчики событий, таймеры, подписки и замыкания, сохранённые в долгоживущих структурах.

Для предотвращения нужно удалять обработчики, отменять подписки и освобождать ненужные ссылки.

# Что такое каррирование и частичное применение?

Каррирование (Currying) - преобразование функции с несколькими аргументами в последовательность функций, каждая из которых принимает следующий аргумент.

```
const add = a => b => a + b;

add(2)(3); // 5
```

Частичное применение (Partial Application) - создание новой функции, в которой заранее зафиксирована часть аргументов исходной функции.

```
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2);

double(5); // 10
```

Разница: каррирование меняет структуру вызова функции на последовательную передачу аргументов, а частичное применение просто фиксирует некоторые аргументы.

Оба подхода используются для переиспользования функций и создания специализированных обработчиков.

# Как работает композиция функций?

Композиция функций (Function Composition) - объединение нескольких функций в одну, когда результат одной функции передаётся следующей.

```
const double = x => x * 2;
const increment = x => x + 1;

const compose = (f, g) => x => f(g(x));

const result = compose(double, increment);

result(3); // 8
```

В математической композиции функции применяются справа налево: сначала `increment`, затем `double`.

Композиция позволяет строить сложные преобразования из небольших независимых функций. Особенно полезна при обработке данных и в функциональном программировании.

Альтернативный подход - pipeline, когда функции последовательно применяются слева направо.

# Что делает функцию чистой?

Чистая функция (Pure Function) удовлетворяет двум условиям:

1. Детерминированность - при одинаковых входных аргументах всегда возвращает одинаковый результат.
2. Отсутствие побочных эффектов - не изменяет внешнее состояние и не выполняет внешне наблюдаемые действия, например запись в файл, изменение DOM или сетевой запрос.

```
// Чистая функция
const sum = (a, b) => a + b;

// Нечистая функция
let total = 0;

function add(value) {
  total += value;
  return total;
}
```

Чистые функции легче тестировать, кешировать и комбинировать, поскольку результат зависит только от аргументов.

При работе с объектами важно не мутировать входные данные. Например, `array.sort()` изменяет исходный массив, поэтому его непосредственное применение к переданному массиву нарушает чистоту функции.

# Чем рекурсия отличается от итерации?

Рекурсия - подход, при котором функция вызывает саму себя для решения более простой версии задачи.

Итерация - повторение операций с помощью циклов, например `for` или `while`.

```
// Рекурсия
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}

// Итерация
function factorialIterative(n) {
  let result = 1;

  for (let i = 2; i <= n; i++) {
    result *= i;
  }

  return result;
}
```

Главное различие - управление состоянием выполнения:

- Рекурсия обычно создаёт новый стековый кадр для каждого вызова. Глубокая рекурсия может вызвать `RangeError: Maximum call stack size exceeded`.
- Итерация обычно использует один стековый кадр и явно обновляет состояние цикла.

Оба подхода могут иметь одинаковую временную сложность, но отличаться расходом памяти.

Рекурсия особенно удобна для деревьев, вложенных структур и алгоритмов «разделяй и властвуй». Итерация обычно предпочтительнее для простых циклов и задач с большой глубиной повторений.

# Что такое tail recursion и можно ли полагаться на её оптимизацию?

Tail Recursion (хвостовая рекурсия) - рекурсия, при которой рекурсивный вызов выполняется в хвостовой позиции, то есть после него функции больше не требуется выполнять вычисления.

```
function factorial(n, acc = 1) {
  if (n <= 1) return acc;

  return factorial(n - 1, acc * n);
}
```

Здесь результат рекурсивного вызова возвращается напрямую.

Proper Tail Calls (PTC) - оптимизация, позволяющая повторно использовать стековый кадр вместо накопления новых, благодаря чему хвостовые вызовы могут выполняться с постоянным расходом стека.

Спецификация ECMAScript предусматривает PTC при определённых условиях в строгом режиме, но поддержка зависит от движка. Например, V8 в Node.js и Chrome не реализует такую оптимизацию.

Полагаться на оптимизацию хвостовой рекурсии в кроссплатформенном JavaScript нельзя. Для глубокой рекурсии безопаснее использовать итерацию или собственный стек.

# Как работают параметры по умолчанию?

Default Parameters позволяют задать значение параметра, если соответствующий аргумент не передан или равен `undefined`.

```
function greet(name = "Guest") {
  return `Hello, ${name}`;
}

greet();          // "Hello, Guest"
greet(undefined); // "Hello, Guest"
greet(null);      // "Hello, null"
```

Особенности:

- Значение по умолчанию применяется только при `undefined`, но не при `null`, `0`, `false` или `""`.
- Выражение по умолчанию вычисляется при каждом вызове функции, если оно необходимо.
- Параметры инициализируются слева направо, поэтому последующие могут использовать предыдущие.
- Выражения по умолчанию имеют собственную область видимости параметров, отделённую от тела функции.

```
function createUser(options = {}) {
  return options;
}

createUser() === createUser(); // false
```

Каждый вызов без аргумента создаёт новый объект, а не переиспользует один общий.

# Чем spread отличается от rest?

Оба используют синтаксис `...`, но выполняют противоположные задачи.

Spread - раскрывает значения массива или другого итерируемого объекта в отдельные элементы либо копирует перечисляемые собственные свойства объекта в новый объект.

```
const numbers = [1, 2, 3];

const copy = [...numbers];
const result = Math.max(...numbers);

const user = { name: "Alex" };
const updated = { ...user, age: 25 };
```

Rest - собирает оставшиеся аргументы функции или элементы деструктурируемой структуры.

```
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}

const [first, ...others] = [1, 2, 3];
// first = 1, others = [2, 3]
```

Разница:

- Spread - раскрывает или копирует данные.
- Rest - собирает оставшиеся данные.

Важно: spread объектов и массивов создаёт поверхностную копию (shallow copy). Вложенные объекты не клонируются, а сохраняют свои ссылки.

# Как работает деструктуризация объектов и массивов?

Деструктуризация (Destructuring) - синтаксис извлечения значений из объектов и итерируемых структур в отдельные переменные.

Для объектов значения извлекаются по именам свойств:

```
const user = { name: "Alex", age: 25 };

const { name, age } = user;
const { name: username } = user;
```

Во втором случае `name` - имя свойства, а `username` - имя создаваемой переменной.

Для массивов значения извлекаются последовательно через протокол итерации:

```
const numbers = [10, 20, 30];

const [first, , third] = numbers;
// first = 10, third = 30
```

Поддерживаются значения по умолчанию, вложенная деструктуризация и rest:

```
const { name = "Guest", ...rest } = user;
```

Значение по умолчанию используется только тогда, когда извлечённое значение равно `undefined`.

Деструктуризация особенно полезна для параметров функций, работы с API и обработки объектов конфигурации.

# Что такое tagged template literal?

Tagged Template Literal - шаблонная строка, перед которой указывается функция-тег, обрабатывающая её статические и динамические части.

```
function tag(strings, ...values) {
  console.log(strings); // ["Hello, ", "!"]
  console.log(values);  // ["Alex"]

  return strings[0] + values[0] + strings[1];
}

tag`Hello, ${"Alex"}!`;
```

Функция-тег получает:

- Первым аргументом - массив статических строковых частей.
- Остальными аргументами - вычисленные значения выражений `${...}`.

У массива строк есть свойство `raw`, содержащее исходные части без обработки escape-последовательностей.

Tagged templates позволяют реализовать собственную обработку шаблонов: экранирование HTML, локализацию, форматирование и построение DSL.

Например, `String.raw` - встроенная функция-тег для работы с исходным представлением строк.

Важно: tagged template сам по себе не обеспечивает защиту от XSS или SQL-инъекций. Безопасность определяется реализацией функции-тега.

# Как реализовать мемоизацию функции?

Мемоизация (Memoization) - оптимизация, при которой результаты вызовов функции кешируются и повторно используются при одинаковых аргументах.

```
function memoize(fn) {
  const cache = new Map();

  return function (arg) {
    if (cache.has(arg)) {
      return cache.get(arg);
    }

    const result = fn(arg);
    cache.set(arg, result);

    return result;
  };
}

const square = memoize(x => x * x);

square(5); // Вычисление
square(5); // Результат из кеша
```

Принцип работы:

1. При вызове проверяется наличие результата в кеше.
2. Если результат найден, он возвращается без повторного вычисления.
3. Если результата нет, функция выполняется и результат сохраняется.

Ограничения:

- Пример поддерживает только один аргумент. Для нескольких необходима подходящая стратегия формирования ключа.
- Объекты в `Map` сравниваются по идентичности, поэтому разные объекты с одинаковым содержимым считаются разными ключами.
- Мемоизация корректна прежде всего для чистых функций.
- Без ограничений кеш может бесконтрольно расти и удерживать объекты в памяти.

Для управления размером кеша используют LRU, TTL или другие стратегии очистки.

# Чем debounce отличается от throttle?

Debounce и throttle - способы ограничения частоты выполнения функции при большом количестве событий.

Debounce откладывает выполнение до тех пор, пока не пройдёт заданный интервал без новых вызовов.

Например, поиск по вводу пользователя: запрос отправляется через 300 мс после последнего нажатия клавиши.

Throttle ограничивает частоту выполнения: функция вызывается не чаще одного раза за заданный интервал.

Например, обработчик `scroll` может обновлять состояние максимум один раз за 100 мс.

| Debounce                                     | Throttle                                         |
|----------------------------------------------|--------------------------------------------------|
| Ожидает паузу между событиями                | Ограничивает частоту вызовов                     |
| Подходит для поиска и валидации              | Подходит для `scroll`, `resize`, `mousemove`     |
| При постоянных событиях может не выполниться | При постоянных событиях выполняется периодически |

Обе техники могут поддерживать режимы `leading` и `trailing` - выполнение в начале или конце интервала.

Для debounce также используют `maxWait`, чтобы гарантировать выполнение даже при непрерывном потоке событий.

# Что такое генератор и как работает `yield`?

Генератор (Generator) - специальная функция, выполнение которой можно приостанавливать и возобновлять.

Объявляется через `function*`, а приостановка выполняется оператором `yield`.

```
function* generate() {
  yield 1;
  yield 2;
  return 3;
}

const iterator = generate();

iterator.next(); // { value: 1, done: false }
iterator.next(); // { value: 2, done: false }
iterator.next(); // { value: 3, done: true }
```

При вызове генератора его тело не выполняется сразу. Вместо этого возвращается объект генератора, реализующий протокол итератора.

Вызов `next()` возобновляет выполнение до следующего `yield`, `return` или завершения функции.

Особенности:

- `yield` возвращает значение наружу и сохраняет состояние выполнения.
- `next(value)` позволяет передать значение внутрь генератора как результат приостановленного выражения `yield`.
- Первый аргумент первого `next()` игнорируется, потому что генератор ещё не достиг `yield`.
- `yield*` делегирует выполнение другому итерируемому объекту.
- `for...of` перебирает значения `yield`, но не включает значение завершающего `return`.

Генераторы применяют для ленивых последовательностей, пользовательских итераторов и поэтапной обработки данных.

# Как реализовать итератор через `Symbol.iterator`?

Протокол итерации определяет, как JavaScript последовательно получает значения из объекта.

Объект считается итерируемым, если содержит метод `[Symbol.iterator]()`, возвращающий итератор.

Итератор должен иметь метод `next()`, который возвращает объект с полями:

- `value` - текущее значение.
- `done` - признак завершения итерации.

```
const range = {
  from: 1,
  to: 3,

  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;

    return {
      next() {
        if (current <= last) {
          return {
            value: current++,
            done: false,
          };
        }

        return { done: true };
      },
    };
  },
};

console.log([...range]); // [1, 2, 3]
```

При использовании `for...of`, spread для итерируемых значений и других механизмов итерации JavaScript вызывает `Symbol.iterator`, затем последовательно вызывает `next()`.

Обычно каждый вызов `Symbol.iterator` создаёт отдельный итератор, позволяющий независимо перебирать объект несколько раз.

Генераторы упрощают реализацию такого протокола, поскольку автоматически создают подходящий итератор.

# Чем CommonJS отличается от ES Modules?

CommonJS (CJS) и ES Modules (ESM) - две системы модулей JavaScript.

CommonJS традиционно используется в Node.js и работает через `require` и `module.exports`.

```
// math.cjs
module.exports = { sum: (a, b) => a + b };

// app.cjs
const { sum } = require("./math.cjs");
```

ES Modules - стандартная модульная система JavaScript, использующая `import` и `export`.

```
// math.mjs
export const sum = (a, b) => a + b;

// app.mjs
import { sum } from "./math.mjs";
```

Основные различия:

| CommonJS                                                | ES Modules                                               |
|---------------------------------------------------------|----------------------------------------------------------|
| `require()` и `module.exports`                          | `import` и `export`                                      |
| Загрузка через `require()` традиционно синхронная       | Поддерживается асинхронная загрузка и выполнение модулей |
| Экспортируемые значения доступны через `module.exports` | Импорты используют live bindings                         |
| Зависимости могут определяться динамически              | Статические `import` анализируются до выполнения         |
| Tree shaking затруднён динамической природой экспорта   | Статическая структура упрощает tree shaking              |
| Основное применение - Node.js                           | Работает в браузерах и Node.js                           |

В Node.js формат модуля определяется расширением файла (`.mjs`, `.cjs`) и настройками пакета, например `"type": "module"`.

Современная разработка преимущественно использует ESM. CommonJS сохраняет значение для существующих Node.js-проектов и совместимости с пакетами.

# Как работают `import`, `export`, `default export` и re-export?

`export` делает объявления доступными для импорта в других ES-модулях.

Именованный экспорт:

```
// math.js
export const PI = 3.14;

export function sum(a, b) {
  return a + b;
}
```

Именованный импорт:

```
import { PI, sum } from "./math.js";
```

`default export` позволяет объявить один экспорт по умолчанию на модуль.

```
// User.js
export default class User {}
```

Импортировать его можно под произвольным локальным именем:

```
import Person from "./User.js";
```

В одном модуле может быть несколько именованных экспортов, но только один `default`.

Re-export - повторный экспорт сущностей из другого модуля без необходимости использовать их внутри текущего.

```
export { sum } from "./math.js";

export { default as User } from "./User.js";

export * from "./utils.js";
```

Это часто используется для создания публичного API модуля через `index.js` (barrel file).

Особенности:

- Статические `import` и `export` должны находиться на верхнем уровне модуля.
- `import * as math` создаёт объект пространства имён модуля.
- `export *` не экспортирует `default` и может создавать неоднозначности при совпадающих именах.
- Импортированные привязки доступны для чтения, но их нельзя переназначать из импортирующего модуля.

# Что такое live bindings в ES Modules?

Live bindings - механизм ES Modules, при котором импортированное имя связано с экспортируемой переменной, а не с копией её значения.

Если экспортирующий модуль изменяет переменную, импортирующие модули видят актуальное значение.

```
// counter.js
export let count = 0;

export function increment() {
  count++;
}
```

```
// app.js
import { count, increment } from "./counter.js";

console.log(count); // 0

increment();

console.log(count); // 1
```

При этом импортирующий модуль не может самостоятельно переназначить привязку:

```
count = 10; // TypeError
```

В отличие от ES Modules, CommonJS работает с экспортируемыми свойствами объекта. Например, при деструктуризации примитивного значения через `require` создаётся отдельная локальная переменная, которая не обновляется при изменении исходного свойства.

Live bindings позволяют модулям разделять актуальное состояние и важны для корректной работы циклических зависимостей.

# Как работает динамический `import()`?

Dynamic Import - механизм асинхронной загрузки ES-модулей во время выполнения программы.

В отличие от статического `import`, динамический `import()` является выражением и возвращает `Promise`, который при успешной загрузке разрешается объектом пространства имён модуля.

```
async function loadModule() {
  const math = await import("./math.js");

  console.log(math.sum(2, 3));
}
```

Основные особенности:

- Может вызываться внутри функций, условий и других выражений.
- Позволяет загружать модуль только тогда, когда он необходим.
- Может использовать вычисляемый путь к модулю, если его поддерживает загрузчик.
- Возвращает `Promise`, поэтому ошибки загрузки и выполнения обрабатываются через `catch` или `try...catch`.

В frontend-разработке применяется для code splitting - разделения приложения на части, загружаемые по необходимости.

```
if (shouldShowChart) {
  const { renderChart } = await import("./chart.js");

  renderChart();
}
```

При повторном импорте уже успешно загруженного модуля его код обычно не выполняется заново благодаря кешированию модулей.

Однако фактическая загрузка отдельных файлов зависит от среды выполнения и сборщика.

# Что такое circular dependency и какие проблемы она вызывает?

Circular Dependency (циклическая зависимость) - ситуация, когда модули прямо или косвенно импортируют друг друга.

Например:

```
// a.js
import { b } from "./b.js";

export const a = b + 1;
```

```
// b.js
import { a } from "./a.js";

export const b = a + 1;
```

В ES Modules циклические зависимости поддерживаются, но могут вызывать проблемы с порядком инициализации.

В данном примере при выполнении одного из модулей может произойти обращение к ещё неинициализированной переменной другого модуля, что приведёт к `ReferenceError` из-за TDZ.

Основные проблемы:

- Доступ к экспортам до их инициализации.
- Неочевидный порядок выполнения модулей.
- Сложность анализа зависимостей и архитектуры.
- Потенциальные зависания при определённых циклических сценариях с асинхронной инициализацией.

В CommonJS циклы тоже разрешены, но модуль может получить частично заполненный `module.exports` другого модуля.

Не каждая циклическая зависимость является ошибкой. Например, функции, импортирующие друг друга, могут корректно работать, если вызываются после завершения инициализации модулей.

Для устранения проблем обычно выносят общую логику в независимый модуль или пересматривают направление зависимостей.

# Что такое top-level await?

Top-Level Await (TLA) - возможность использовать `await` непосредственно на верхнем уровне ES-модуля, без оборачивания в `async`-функцию.

```
// config.js
const response = await fetch("/config.json");

export const config = await response.json();
```

Когда модуль использует top-level await, его выполнение может быть приостановлено до завершения асинхронной операции.

Модули, которые зависят от него через статический импорт, ожидают завершения его асинхронной инициализации, прежде чем выполнять собственный код. При этом независимые модули могут продолжать выполняться.

Основные особенности:

- Работает в ES Modules, но не в обычных скриптах и стандартных CommonJS-модулях.
- Позволяет выполнять асинхронную инициализацию до предоставления готовых экспортов.
- Может задерживать выполнение зависимых модулей.
- При ошибке асинхронной инициализации выполнение зависимых модулей также завершается ошибкой.
- Может усложнять циклические зависимости и приводить к зависанию при неразрешённых асинхронных операциях.

Top-level await поддерживается современными браузерами и актуальными версиями Node.js.

Его используют для загрузки конфигурации, инициализации ресурсов и других операций, которые должны завершиться до использования модуля.
