# Для чего нужен HTML и какова его роль по отношению к CSS и JavaScript?

HTML (HyperText Markup Language) - язык разметки, который определяет структуру, содержимое и семантику веб-страницы.

- HTML описывает, что находится на странице: заголовки, текст, изображения, ссылки, формы.
- CSS управляет представлением: цветами, размерами, расположением, адаптивностью.
- JavaScript реализует поведение: обработку событий, динамическое изменение интерфейса, взаимодействие с API.

Браузер преобразует HTML в DOM (Document Object Model) - дерево объектов, с которыми может взаимодействовать JavaScript. CSS применяется к элементам этого дерева для формирования визуального представления.

HTML не зависит от CSS и JavaScript: корректно размеченная страница может оставаться содержательной и функциональной даже без них.

# Из каких частей состоит HTML-документ?

HTML-документ обычно состоит из следующих частей:

- `<!DOCTYPE html>` - объявление типа документа, включающее стандартный режим отображения.
- `<html>` - корневой элемент, содержащий документ. Атрибут `lang` указывает язык содержимого.
- `<head>` - метаданные: кодировка, заголовок страницы, подключение стилей и другие служебные сведения.
- `<body>` - основное содержимое страницы, доступное пользователю.

Пример:

```
<!DOCTYPE html>
<html lang="ru">
  <head>
    <meta charset="UTF-8" />
    <meta
      name="viewport"
      content="width=device-width, initial-scale=1"
    />
    <title>Моя страница</title>
  </head>
  <body>
    <h1>Привет, мир!</h1>
  </body>
</html>
```

Браузер разбирает HTML и формирует DOM-дерево. При этом он может автоматически исправлять некоторые ошибки разметки, например добавлять пропущенные элементы или закрывать определённые теги.

# Как браузер интерпретирует `<!DOCTYPE html>`?

`<!DOCTYPE html>` - объявление типа документа, которое сообщает браузеру, что страницу необходимо обрабатывать в стандартном режиме (no-quirks mode).

У браузеров существуют три основных режима:

- Standards (no-quirks) - поведение соответствует современным стандартам.
- Quirks - режим совместимости со старыми страницами, допускающий исторические особенности CSS и компоновки.
- Limited-quirks - почти стандартный режим с отдельными особенностями совместимости.

Без корректного `DOCTYPE` браузер может перейти в quirks mode, что приведёт к неожиданным различиям в отображении.

`<!DOCTYPE html>` не является HTML-элементом, не имеет закрывающего тега и не определяет версию HTML. В DOM ему соответствует узел `DocumentType`.

# Что такое HTML-элемент и чем он отличается от тега?

Тег - синтаксическая конструкция HTML, обозначающая начало или конец элемента: `<p>` или `</p>`.

HTML-элемент - полноценная структурная единица документа, включающая начальный тег, содержимое и конечный тег, если он предусмотрен.

Например:

```
<p class="text">Привет!</p>
```

Здесь:

- `<p class="text">` - открывающий тег с атрибутом.
- `Привет!` - текстовое содержимое.
- `</p>` - закрывающий тег.
- Вся конструкция - HTML-элемент.

Существуют void-элементы, например `<img>`, `<input>`, `<br>`, которые не могут содержать дочерние узлы и не имеют закрывающего тега.

HTML-элементы представлены объектами в DOM, тогда как теги относятся к исходной разметке.

# Какие атрибуты считаются глобальными?

Глобальные атрибуты - атрибуты, которые разрешено использовать практически на любых HTML-элементах.

Основные:

- `id` - уникальный идентификатор элемента в документе.
- `class` - набор классов, используемых для CSS и JavaScript.
- `style` - встроенные CSS-стили.
- `title` - дополнительная информация об элементе.
- `lang` - язык содержимого.
- `dir` - направление текста: `ltr`, `rtl`, `auto`.
- `hidden` - скрытие содержимого.
- `tabindex` - управление фокусировкой и порядком навигации с клавиатуры.
- `contenteditable` - возможность редактирования содержимого.
- `draggable` - управление возможностью перетаскивания.
- `data-*` - пользовательские данные.
- `role` и `aria-*` - описание семантики и состояний для вспомогательных технологий.
- `inert` - исключение элемента и его потомков из пользовательского взаимодействия и фокусировки.

Глобальность означает, что атрибут допустим для разных элементов, но не гарантирует одинаковую практическую пользу. Например, `contenteditable` и `draggable` имеют смысл лишь в соответствующих сценариях.

# Что такое семантическая разметка и зачем она нужна?

Семантическая разметка - использование HTML-элементов в соответствии с их смысловым назначением, а не только внешним видом.

Например, `<button>` обозначает действие, `<nav>` - навигацию, `<article>` - самостоятельный материал.

Преимущества:

- Доступность (a11y) - скринридеры и другие вспомогательные технологии лучше понимают структуру и назначение элементов.
- SEO - поисковые системы получают дополнительные сведения о структуре и содержании страницы.
- Поддерживаемость - разработчику проще понять назначение элементов.
- Нативное поведение - семантические элементы предоставляют встроенные возможности браузера, например клавиатурное управление кнопками.

Семантические элементы не гарантируют доступность автоматически: важны также корректная вложенность, названия элементов управления и поведение интерфейса.

# Когда использовать `section`, `article`, `aside`, `main`, `header` и `footer`?

- `section` - тематически объединённая часть документа, обычно имеющая заголовок. Например, раздел отзывов или характеристик товара.
- `article` - самостоятельный материал, который имеет смысл отдельно от остальной страницы: статья, пост, комментарий, карточка новости.
- `aside` - дополнительный контент, косвенно связанный с основным: боковая панель, рекомендации, пояснения.
- `main` - основное уникальное содержимое страницы. Обычно используется один видимый `<main>`.
- `header` - вводная часть страницы или раздела: заголовок, логотип, навигация, вводная информация.
- `footer` - завершающая часть страницы или раздела: авторство, ссылки, контакты, юридическая информация.

`header` и `footer` могут находиться как на уровне страницы, так и внутри `article` или `section`.

Главный критерий выбора - смысл содержимого, а не визуальное расположение. Если контейнер нужен исключительно для стилизации, обычно достаточно `<div>`.

# Чем `button` отличается от `a` с обработчиком клика?

`<button>` предназначен для действий, а `<a href>` - для навигации.

`<button>`:

- Активируется клавишами `Enter` и `Space`.
- Поддерживает `disabled`.
- Участвует в работе HTML-форм.
- Имеет нативную семантику кнопки.

`<a href>`:

- Предназначен для перехода по URL, включая якоря страницы.
- Поддерживает открытие в новой вкладке, копирование адреса и контекстное меню.
- Обычно активируется клавишей `Enter`.
- Не поддерживает нативный `disabled`.

Добавление `onClick` к `<a>` не превращает ссылку в полноценную кнопку. Особенно если отсутствует `href`: тогда элемент теряет стандартное поведение ссылки и клавиатурную доступность.

Правило: отправка формы, открытие модального окна, удаление записи - `<button>`. Переход на другую страницу - `<a>`.

Внутри формы следует указывать `type="button"` для кнопок, которые не должны отправлять форму, поскольку по умолчанию используется `submit`.

# Чем `strong` отличается от `b`, а `em` от `i`?

`<strong>` обозначает особую важность, серьёзность или срочность содержимого. `<b>` привлекает внимание к тексту, не придавая ему дополнительной важности.

Например, предупреждение об опасности уместно выделить через `<strong>`, а ключевое слово в описании - через `<b>`.

`<em>` обозначает смысловое ударение, которое способно менять интерпретацию фразы. `<i>` используется для текста, отличающегося по характеру от окружающего: терминов, иностранных выражений, мыслей персонажа.

По умолчанию браузеры обычно отображают `strong` и `b` жирным шрифтом, а `em` и `i` курсивом.

Однако их семантика различается, а внешний вид можно независимо изменить через CSS.

# Как правильно разметить навигационное меню?

Для основных навигационных блоков используют `<nav>`, а для группы ссылок обычно `<ul>` с элементами `<li>`.

```
<nav aria-label="Основная навигация">
  <ul>
    <li><a href="/">Главная</a></li>
    <li><a href="/catalog">Каталог</a></li>
    <li><a href="/contacts">Контакты</a></li>
  </ul>
</nav>
```

`<nav>` обозначает навигационную область, позволяя вспомогательным технологиям распознавать её назначение.

Если на странице несколько навигационных областей, их стоит различать доступными названиями, например через `aria-label`.

Текущую страницу можно обозначить `aria-current="page"` на соответствующей ссылке.

Не каждую группу ссылок нужно помещать в `<nav>`: элемент предназначен преимущественно для значимых навигационных блоков.

# Как семантически оформить изображение с подписью?

Для изображения с подписью используют `<figure>` и `<figcaption>`.

```
<figure>
  <img
    src="architecture.png"
    alt="Схема архитектуры приложения"
  />
  <figcaption>
    Рисунок 1. Архитектура приложения
  </figcaption>
</figure>
```

- `<figure>` объединяет самостоятельный иллюстративный материал.
- `<figcaption>` задаёт подпись к нему.
- `alt` описывает изображение для пользователей, которые не могут его увидеть.

`figcaption` может находиться первым или последним дочерним элементом `figure`.

Важно: `alt` и `figcaption` решают разные задачи. `alt` предоставляет текстовую альтернативу изображению, а `figcaption` представляет видимую подпись. Не нужно дублировать одинаковый текст без необходимости.

# Когда использовать `ul`, `ol` и `dl`?

- `<ul>` - неупорядоченный список, где последовательность элементов не имеет значения. Например, перечень возможностей приложения.
- `<ol>` - упорядоченный список, где порядок элементов важен. Например, пошаговая инструкция или рейтинг.
- `<dl>` - список ассоциаций между названиями и значениями, например терминами и определениями либо характеристиками и их значениями.

Для `ul` и `ol` элементы списка оформляют через `<li>`.

Для `dl` используют `<dt>` (название или термин) и `<dd>` (значение или описание).

`<dl>` поддерживает несколько названий для одного значения и несколько значений для одного названия.

Выбирать тип списка нужно по смыслу данных, а не по желаемому виду маркеров: оформление контролируется CSS.

# Чем блочные элементы отличаются от строчных?

Исторически HTML-элементы делили на блочные и строчные. В современном HTML это прежде всего различие в стандартных CSS-значениях `display`, а не в категориях HTML-элементов.

Блочные элементы (`display: block`):

- Обычно начинаются с новой строки.
- По умолчанию занимают доступную ширину содержащего блока.
- Участвуют в блочной компоновке, позволяющей задавать ширину, высоту и внешние отступы.

Примеры: `<div>`, `<p>`, `<section>`.

Строчные элементы (`display: inline`):

- Располагаются внутри текстового потока.
- Могут переноситься на несколько строк.
- Для обычных нереплейсных inline-элементов `width` и `height` не действуют, а вертикальные `margin` не раздвигают строки.

Примеры: `<span>`, `<a>`, `<strong>`.

Есть исключения: `<img>` по умолчанию строчный, но является замещаемым элементом (replaced element), поэтому поддерживает размеры.

Через CSS можно изменить отображение элемента, например `display: flex`, но его HTML-семантика и правила допустимой вложенности от этого не изменятся.

# Что такое категории контента HTML и почему вложенность элементов бывает невалидной?

Категории контента - система классификации HTML-элементов, определяющая их назначение и допустимые отношения друг с другом.

Основные категории:

- Metadata content - метаданные документа: `meta`, `link`, `title`.
- Flow content - большинство элементов содержимого страницы.
- Phrasing content - текст и встроенные в него элементы: `span`, `strong`, `a`.
- Sectioning content - элементы, формирующие тематические разделы: `article`, `section`, `nav`, `aside`.
- Heading content - заголовки `h1`-`h6`, `hgroup`.
- Embedded content - встроенные ресурсы: `img`, `iframe`, `video`.
- Interactive content - интерактивные элементы: `button`, `select`, `input`, ссылки с `href`.

Один элемент может принадлежать нескольким категориям одновременно.

У каждого элемента существует content model - правило, определяющее, какие дочерние элементы допустимы.

Например:

```
<!-- Невалидно -->
<p>
  Текст
  <div>Блок</div>
</p>
```

`<p>` допускает phrasing content, но не `<div>`. Поэтому HTML-парсер автоматически завершит абзац перед `<div>`, и фактическое DOM-дерево будет отличаться от ожидаемого.

Аналогично нельзя вкладывать `<button>` внутрь другого `<button>`.

Невалидная вложенность способна приводить к неожиданным изменениям DOM, проблемам доступности и ошибкам гидратации в React.

# В чём назначение `head`, `title`, `meta`, `link` и `base`?

- `<head>` - контейнер метаданных документа, обычно не отображаемых как содержимое страницы.
- `<title>` - название документа, используемое во вкладке браузера, истории и закладках. Может использоваться поисковыми системами.
- `<meta>` - метаданные: кодировка, описание, настройки viewport и другие сведения.
- `<link>` - объявление отношений с внешними ресурсами: CSS, иконками, альтернативными представлениями, подсказками загрузки.
- `<base>` - базовый URL для разрешения относительных ссылок документа и/или целевой контекст навигации по умолчанию.

Например:

```
<base href="https://example.com/docs/" />
<a href="guide">Документация</a>
```

Ссылка будет вести на `https://example.com/docs/guide`.

`<base>` требует осторожности, поскольку влияет на относительные URL по всему документу, включая ссылки с `href="#id"`.

# Зачем нужен `meta name="viewport"`?

`<meta name="viewport">` управляет параметрами layout viewport на мобильных устройствах.

Стандартная запись:

```
<meta
  name="viewport"
  content="width=device-width, initial-scale=1"
/>
```

- `width=device-width` - устанавливает ширину layout viewport равной ширине экрана устройства в CSS-пикселях.
- `initial-scale=1` - задаёт начальный масштаб отображения.

Без этого тега мобильный браузер может использовать широкий виртуальный viewport и уменьшать страницу целиком, чтобы она поместилась на экране.

Это мешает корректной работе адаптивной вёрстки и CSS media queries.

Не рекомендуется запрещать масштабирование через `user-scalable=no` или жёстко ограничивать `maximum-scale`, поскольку это ухудшает доступность для пользователей с нарушениями зрения.

# Для чего используют `data-*` атрибуты?

`data-*` - пользовательские HTML-атрибуты для хранения дополнительных данных, связанных с элементом.

Например:

```
<button data-user-id="42">Удалить</button>
```

JavaScript предоставляет доступ к ним через `dataset`:

```
const button = document.querySelector("button");

console.log(button.dataset.userId); // "42"
```

Имена преобразуются из `kebab-case` в `camelCase`: `data-user-id` становится `dataset.userId`.

Особенности:

- Значения всегда представлены строками.
- Данные можно читать и изменять через JavaScript.
- CSS позволяет обращаться к ним через селекторы атрибутов.
- Они подходят для идентификаторов, настроек и технических метаданных.

Важно: `data-*` не предназначены для хранения секретов, поскольку доступны в DOM. Также ими не следует заменять стандартные HTML-атрибуты, когда для данных уже существует подходящая семантика.

# Как работает атрибут `hidden` и чем он отличается от CSS-скрытия?

`hidden` - глобальный HTML-атрибут, указывающий, что содержимое элемента не должно отображаться пользователю.

```
<div hidden>Скрытый контент</div>
```

В обычном состоянии `hidden` браузер, как правило, скрывает элемент через `display: none`. Элемент исключается из визуальной компоновки и дерева доступности.

Отличия от CSS:

- `display: none` - полностью исключает элемент из компоновки.
- `visibility: hidden` - скрывает элемент, сохраняя занимаемое пространство.
- `opacity: 0` - делает элемент прозрачным, но сохраняет его в компоновке и потенциально доступным для взаимодействия.
- `hidden` - семантически обозначает содержимое как неактуальное для текущего состояния страницы.

Существует также `hidden="until-found"`: содержимое остаётся скрытым, но браузер может раскрыть его при поиске по странице или переходе к якорю. Поддержка этого режима зависит от браузера.

`hidden` не обеспечивает абсолютного скрытия: CSS может переопределить его отображение. Он также не отключает выполнение скриптов внутри элемента и не защищает данные от просмотра через DevTools.&#x20;

# Чем отличаются `defer`, `async` и обычное подключение `script`?

Различие заключается в том, когда браузер загружает и выполняет JavaScript относительно HTML-парсинга.

Обычный `<script src="...">`:

- При обнаружении скрипта HTML-парсер приостанавливается.
- Браузер загружает скрипт, если он ещё не загружен, и выполняет его.
- После выполнения продолжается разбор HTML.

`<script defer src="...">`:

- Скрипт загружается параллельно разбору HTML.
- Выполняется после завершения парсинга документа.
- Сохраняет порядок выполнения относительно других `defer`-скриптов.
- Завершает выполнение до события `DOMContentLoaded`.

`<script async src="...">`:

- Загружается параллельно разбору HTML.
- Выполняется сразу после готовности, прерывая парсинг на время выполнения.
- Порядок выполнения нескольких `async`-скриптов не гарантирован.
- Не задерживает `DOMContentLoaded` до своего завершения.

Когда использовать:

`defer` - для основного кода приложения, которому требуется готовый DOM и предсказуемый порядок выполнения.

`async` - для независимых скриптов, например аналитики.

Оба атрибута в описанном виде относятся к внешним классическим скриптам. У встроенных классических скриптов без `src` они не работают. Модули `type="module"` по умолчанию ведут себя как отложенные скрипты.&#x20;

# Для чего нужен `type="module"` у тега `script`?

`type="module"` сообщает браузеру, что JavaScript нужно обрабатывать как ES-модуль, а не как классический скрипт.

```
<script type="module" src="./main.js"></script>
```

Основные особенности:

- Поддерживает `import` и `export`.
- Позволяет разбивать приложение на независимые модули с явными зависимостями.
- Каждый модуль имеет собственную область видимости.
- Автоматически использует строгий режим (`strict mode`).
- По умолчанию выполняется после завершения HTML-парсинга.
- Модули и их зависимости загружаются как граф модулей.

В отличие от классических скриптов, переменные верхнего уровня модуля не становятся свойствами `window`.

Для междоменных запросов модулей применяется CORS. Поэтому сервер должен разрешать соответствующие запросы, а JavaScript-файлы необходимо отдавать с корректным MIME-типом.

У модульного скрипта `defer` не имеет эффекта, но `async` может изменить стандартный порядок выполнения.&#x20;

# Зачем используют `noscript`?

`<noscript>` предоставляет альтернативный HTML-контент, который отображается, когда браузер не поддерживает выполнение скриптов или JavaScript отключён.

```
<noscript>
  Для работы приложения необходим JavaScript.
</noscript>
```

Используется для:

- Сообщений о необходимости JavaScript.
- Альтернативной навигации.
- Предоставления базовой функциональности без скриптов.
- Резервного содержимого для страниц, зависящих от JavaScript.

Важно: `noscript` не является универсальным механизмом обработки ошибок JavaScript. Если скрипт загрузился, но завершился с ошибкой, содержимое `noscript` автоматически не появится.

# Чем `iframe` отличается от `embed` и `object`?

Все три элемента позволяют встраивать внешнее содержимое, но используют разные механизмы.

`<iframe>` создаёт вложенный контекст просмотра с отдельным документом, DOM и объектом `window`.

Применяется для встраивания других HTML-страниц, карт, видеоплееров и сторонних приложений. Взаимодействие с содержимым ограничивается Same-Origin Policy, а дополнительные ограничения задаются через `sandbox`.

`<embed>` встраивает внешний ресурс, например PDF или SVG, используя возможности браузера. Не имеет механизма резервного содержимого через дочерние элементы.

`<object>` предназначен для встраивания внешних ресурсов и позволяет указывать резервное содержимое между открывающим и закрывающим тегами.

Например:

```
<object data="document.pdf" type="application/pdf">
  <a href="document.pdf">Открыть PDF</a>
</object>
```

В современном вебе `iframe` обычно используют для HTML-документов, а `object` и `embed` - для поддерживаемых браузером внешних форматов. Исторические браузерные плагины, ради которых часто применялись последние два элемента, практически вышли из употребления.

# Какие ограничения безопасности можно задать через `iframe sandbox`?

Атрибут `sandbox` ограничивает возможности документа, загруженного внутри `<iframe>`.

```
<iframe
  src="https://example.com/widget"
  sandbox="allow-scripts"
></iframe>
```

Пустой `sandbox` включает набор ограничений по умолчанию. Отдельные возможности возвращаются через разрешения `allow-*`.

Основные:

- `allow-scripts` - разрешает выполнение JavaScript.
- `allow-forms` - разрешает отправку форм.
- `allow-same-origin` - позволяет сохранить обычное происхождение документа вместо изолированного.
- `allow-popups` - разрешает открытие новых окон.
- `allow-modals` - разрешает модальные диалоги.
- `allow-top-navigation` - разрешает навигацию верхнего окна.
- `allow-top-navigation-by-user-activation` - разрешает такую навигацию только при пользовательском действии.
- `allow-downloads` - разрешает загрузки.

Без `allow-same-origin` документ получает специальное непрозрачное происхождение (opaque origin), что ограничивает доступ к cookies, хранилищам и другим ресурсам, зависящим от origin.

Критическая особенность: опасно одновременно задавать `allow-scripts` и `allow-same-origin` для iframe с содержимым того же origin, что и родительская страница. Такой документ способен снять ограничения `sandbox`.

Для изоляции недоверенного содержимого желательно использовать отдельный origin.&#x20;

# Для чего нужны `template`, `slot` и Web Components?

Web Components - набор браузерных технологий для создания переиспользуемых пользовательских HTML-элементов с изолированной внутренней структурой.

Основные составляющие:

`<template>` - хранит HTML-шаблон, который не отображается и не активируется при первоначальном разборе страницы.

Содержимое доступно через `template.content` как `DocumentFragment`. Его можно клонировать и добавлять в DOM.

`<slot>` - определяет место внутри Shadow DOM, в которое будет отображаться содержимое, переданное пользовательскому компоненту извне.

Custom Elements - позволяют создавать собственные HTML-элементы через `customElements.define()`, используя классы JavaScript.

Shadow DOM - создаёт отдельное DOM-поддерево компонента, обеспечивая инкапсуляцию структуры и стилей.

Например, компонент `<user-card>` может иметь собственную разметку и стили, а его содержимое передаваться через слоты.

При этом Shadow DOM не является механизмом безопасности: он обеспечивает инкапсуляцию компонентов, а не защиту секретных данных.

# В каких случаях использовать `dialog`?

`<dialog>` - нативный HTML-элемент для создания модальных и немодальных диалоговых окон.

Типичные сценарии:

- Подтверждение удаления.
- Редактирование данных в отдельном окне.
- Форма авторизации.
- Диалог выбора или подтверждения действия.

Основные методы:

```
dialog.show();      // Немодальный диалог
dialog.showModal(); // Модальный диалог
dialog.close();     // Закрытие
```

При `showModal()` браузер автоматически:

- Помещает диалог в верхний слой отображения (top layer).
- Блокирует взаимодействие с остальной частью документа через механизм `inert`.
- Управляет начальной фокусировкой и модальным перемещением фокуса.
- Поддерживает закрытие через `Escape` и событие `cancel`.
- Позволяет стилизовать фон через `::backdrop`.

Диалог также можно закрывать формой с `method="dialog"`.

Нативный `<dialog>` предпочтительнее самодельного модального окна из `<div>`, поскольку многие механизмы доступности уже реализованы браузером. Однако необходимо обеспечить понятное название диалога и удобный способ его закрытия.&#x20;

# Чем SVG отличается от Canvas?

SVG (Scalable Vector Graphics) - векторная графика, представленная набором геометрических элементов.

Canvas - растровая область рисования, которой управляют через JavaScript API, например Canvas 2D или WebGL.

Основные различия:

| Критерий        | SVG                                 | Canvas                                                       |
|-----------------|-------------------------------------|--------------------------------------------------------------|
| Графика         | Векторная                           | Растровая область                                            |
| Масштабирование | Без потери чёткости                 | Может требовать перерисовки                                  |
| DOM             | Фигуры представлены элементами      | Отдельных DOM-элементов для фигур нет                        |
| Стилизация      | CSS и атрибуты                      | Через API рисования                                          |
| События         | Можно назначать отдельным элементам | Попадание в нарисованные объекты обычно определяется вручную |
| Применение      | Иконки, схемы, диаграммы            | Игры, графические редакторы, сложная динамическая графика    |

Ключевое различие - модель работы.

В SVG браузер хранит структуру объектов и самостоятельно перерисовывает их при изменении.

В Canvas JavaScript отправляет команды рисования. После рисования браузер не хранит отдельные фигуры как DOM-объекты, поэтому при изменениях приложение обычно должно перерисовать необходимые области.

Canvas может быть эффективнее для большого количества динамически изменяющихся объектов, но SVG удобнее, когда важны отдельные интерактивные элементы, семантика и управление через DOM.

# Какие преимущества даёт `picture` по сравнению с `img`?

`<picture>` позволяет задавать разные источники изображения в зависимости от условий, используя вложенные `<source>`.

Основные преимущества:

- Art direction - возможность показывать разные кадрирования или композиции на разных экранах.
- Форматы - возможность предложить AVIF, WebP и резервный JPEG или PNG.
- Адаптивность - выбор источников по медиазапросам через `media`.

Например:

```
<picture>
  <source
    media="(max-width: 600px)"
    srcset="mobile.jpg"
  />
  <source
    type="image/avif"
    srcset="desktop.avif"
  />
  <img src="desktop.jpg" alt="Пейзаж" />
</picture>
```

Браузер последовательно проверяет подходящие `<source>` и выбирает первый совместимый вариант. Если подходящий источник не найден, используется `<img>`.

Сам `<img>` остаётся обязательным: именно он представляет изображение, содержит `alt` и является резервным вариантом.

Если требуется только выбрать разрешение одного и того же изображения, зачастую достаточно обычного `<img>` с `srcset` и `sizes`.

# Как работают `srcset` и `sizes` у изображений?

`srcset` задаёт несколько вариантов изображения, а `sizes` сообщает браузеру ожидаемую ширину изображения в CSS-пикселях при разных условиях.

У `srcset` есть два основных типа дескрипторов.

Плотность пикселей (`x`):

```
<img
  src="image.jpg"
  srcset="image.jpg 1x, image@2x.jpg 2x"
  alt="Пример"
/>
```

Браузер выбирает подходящий ресурс с учётом плотности пикселей устройства (`devicePixelRatio`) и других факторов.

Физическая ширина файла (`w`):

```
<img
  src="medium.jpg"
  srcset="
    small.jpg 400w,
    medium.jpg 800w,
    large.jpg 1200w
  "
  sizes="(max-width: 600px) 100vw, 600px"
  alt="Пример"
/>
```

Здесь:

- `srcset` перечисляет изображения и их фактическую ширину.
- `sizes` указывает, что при ширине viewport до `600px` изображение предполагается показывать на всю ширину viewport, а иначе - шириной `600px`.
- Браузер учитывает `sizes`, `devicePixelRatio`, сетевые условия и собственные алгоритмы выбора.

Например, если ожидаемая ширина изображения составляет `600` CSS-пикселей, а DPR равен `2`, браузеру для максимальной чёткости желательно получить ресурс шириной около `1200` физических пикселей.

Нельзя смешивать дескрипторы `w` и `x` в одном `srcset`. Атрибут `sizes` используется именно с вариантами `w`.

Важно: `sizes` не задаёт фактический CSS-размер изображения - он предоставляет браузеру информацию для выбора файла. Реальные размеры определяются CSS и компоновкой.&#x20;

# Что означает `loading="lazy"` и когда его не стоит применять?

`loading="lazy"` включает отложенную загрузку изображений и iframe, позволяя браузеру не загружать их сразу, если они находятся достаточно далеко от видимой области страницы.

```
<img
  src="photo.jpg"
  loading="lazy"
  width="800"
  height="600"
  alt="Фотография"
/>
```

Браузер самостоятельно определяет момент начала загрузки с учётом расстояния до viewport и других факторов.

Преимущества:

- Уменьшение первоначального сетевого трафика.
- Снижение конкуренции за пропускную способность.
- Ускорение первоначальной загрузки длинных страниц.

Не стоит применять `lazy` к изображениям, необходимым сразу при открытии страницы, особенно к главному изображению, влияющему на Largest Contentful Paint (LCP).

Для критически важного изображения предпочтительнее `loading="eager"` или стандартная загрузка. При необходимости можно использовать `fetchpriority="high"`.

Рекомендуется также указывать `width` и `height`, чтобы браузер мог заранее зарезервировать пространство и избежать сдвигов макета (CLS).

# Чем `preload`, `prefetch`, `preconnect` и `dns-prefetch` отличаются друг от друга?

Все четыре механизма представляют собой подсказки браузеру для оптимизации загрузки, но решают разные задачи.

`preload` - ранняя загрузка ресурса для текущей страницы.

```
<link
  rel="preload"
  href="/font.woff2"
  as="font"
  type="font/woff2"
  crossorigin
/>
```

Браузер заранее загружает важный ресурс, даже если потребность в нём обнаружится позже. Атрибут `as` указывает тип ресурса, влияя на приоритет и обработку запроса.

`prefetch` - предварительная загрузка для будущей навигации.

```
<link rel="prefetch" href="/next-page.html" />
```

Браузер может заранее скачать и закешировать ресурс, который предположительно понадобится позже.

`preconnect` - предварительное установление соединения.

```
<link
  rel="preconnect"
  href="https://api.example.com"
/>
```

Браузер заранее выполняет необходимые этапы установления соединения: DNS-разрешение, TCP и TLS (в зависимости от протокола).

`dns-prefetch` - предварительное разрешение домена.

```
<link
  rel="dns-prefetch"
  href="https://api.example.com"
/>
```

Браузер заранее узнаёт IP-адрес домена, но не устанавливает полноценное соединение.

Главное отличие:

- `preload` - ресурс нужен на текущей странице.
- `prefetch` - ресурс может понадобиться позже.
- `preconnect` - заранее подготовить соединение.
- `dns-prefetch` - заранее разрешить DNS-имя.

Это подсказки, и браузер может не выполнить их в зависимости от условий. Поддержка `prefetch` различается между браузерами.

Избыточное использование этих механизмов способно ухудшить производительность из-за дополнительного трафика и конкуренции за ресурсы.&#x20;

# Как браузер выбирает кодировку документа и зачем нужна UTF-8?

Кодировка определяет, как последовательность байтов преобразуется в символы текста.

Браузер определяет кодировку HTML-документа на основании нескольких источников:

1. BOM (Byte Order Mark) - специальная последовательность байтов в начале файла, имеющая высокий приоритет.
2. HTTP-заголовок `Content-Type` - может содержать параметр `charset`.
3. `<meta charset="UTF-8">` - объявление кодировки непосредственно в HTML.
4. Резервные алгоритмы - если кодировка явно не определена, браузер использует предусмотренные стандартом механизмы определения.

При этом стандарт предусматривает дополнительные детали, например пользовательское переопределение кодировки.

Для HTML рекомендуется указывать:

```
<meta charset="UTF-8" />
```

Объявление кодировки должно находиться в первых 1024 байтах документа.

UTF-8 - наиболее распространённая кодировка Unicode, способная представлять символы практически всех письменностей, специальные знаки и эмодзи.

Её преимущества:

- Совместимость с ASCII.
- Поддержка множества языков в одном документе.
- Отсутствие необходимости переключать кодировки между языками.
- Широкая поддержка браузерами, серверами и инструментами разработки.

Если файл сохранён в одной кодировке, а браузер интерпретирует его в другой, возникает mojibake - некорректное отображение текста в виде нечитаемых символов.&#x20;

# Что такое progressive enhancement и graceful degradation?

Progressive enhancement и graceful degradation - подходы к обеспечению работоспособности веб-приложений при разных возможностях браузера и окружения.

Progressive enhancement (прогрессивное улучшение) предполагает разработку от минимальной работоспособной версии к более функциональной:

1. HTML обеспечивает базовую структуру и доступность содержимого.
2. CSS улучшает оформление.
3. JavaScript добавляет интерактивность и дополнительные возможности.

Например, HTML-форма может отправлять данные обычным HTTP-запросом, а JavaScript улучшает её, позволяя отправлять запрос через `fetch` без перезагрузки страницы.

Graceful degradation (постепенная деградация) предполагает создание полноценного современного решения с последующим обеспечением приемлемой работы при отсутствии отдельных возможностей.

Например, приложение использует современный CSS Grid, но предусматривает более простую компоновку для браузеров без его поддержки.

Ключевое различие:

- Progressive enhancement - сначала базовая функциональность, затем улучшения.
- Graceful degradation - сначала полноценная функциональность, затем резервные сценарии.

Оба подхода направлены на устойчивость интерфейса, но progressive enhancement изначально рассматривает базовую доступность и работоспособность как фундамент приложения.
