# Что такое прототип объекта и прототипная цепочка?

Прототип - объект, от которого другой объект может наследовать свойства и методы. Каждый обычный объект JavaScript имеет внутреннюю ссылку `[[Prototype]]` на другой объект или `null`.

Прототипная цепочка - последовательность объектов, связанных через `[[Prototype]]`.

При обращении к свойству JavaScript:

1. Ищет свойство непосредственно в объекте.
2. Если не находит, проверяет его прототип.
3. Продолжает поиск по цепочке до обнаружения свойства или достижения `null`.
4. Если свойство не найдено, возвращает `undefined`.

Наследуемые свойства не копируются в объект, а находятся через механизм делегирования. Собственное свойство с тем же именем перекрывает наследуемое.

Для работы с прототипами используются `Object.getPrototypeOf()` и `Object.setPrototypeOf()`. Изменять прототип существующего объекта обычно не рекомендуется из-за возможного ухудшения производительности.

# Как работает наследование через `Object.create()`?

`Object.create(proto)` создаёт новый объект, устанавливая `proto` в качестве его `[[Prototype]]`.

```
const animal = {
  speak() {
    return "Sound";
  }
};

const dog = Object.create(animal);

dog.name = "Rex";

dog.speak(); // "Sound"
```

У `dog` собственное свойство `name`, а метод `speak` доступен через прототип `animal`.

Особенности:

- `Object.create()` не вызывает конструктор.
- Наследуемые методы и свойства не копируются.
- Изменения в прототипе могут отражаться на наследующих объектах.
- `Object.create(null)` создаёт объект без прототипа, у которого нет унаследованных методов `Object.prototype`.

Второй аргумент `Object.create()` позволяет сразу определить собственные свойства через дескрипторы.

# Что делает оператор `new`?

Оператор `new` вызывает функцию как конструктор, создавая и инициализируя объект.

Для обычной функции-конструктора механизм следующий:

1. Создаётся новый объект.
2. Его `[[Prototype]]` устанавливается в `Constructor.prototype`, если это объект.
3. Конструктор вызывается с `this`, указывающим на новый объект.
4. Если конструктор явно возвращает объект, результатом `new` становится этот объект. Иначе возвращается созданный экземпляр.

```
function User(name) {
  this.name = name;
}

const user = new User("Alex");
```

При использовании `new` с классами задействован тот же механизм конструирования `[[Construct]]`, но инициализация может отличаться, особенно при наследовании через `extends`.

Не все функции поддерживают `new`. Например, стрелочные функции не являются конструкторами.

# Как связаны `prototype` функции и `[[Prototype]]` объекта?

Это разные механизмы:

- `prototype` - обычное свойство функции-конструктора, определяющее прототип будущих экземпляров.
- `[[Prototype]]` - внутренняя ссылка объекта на его прототип, используемая при поиске свойств.

```
function User() {}

const user = new User();

Object.getPrototypeOf(user) === User.prototype;
// true
```

При создании экземпляра через `new` объект из `User.prototype` становится его `[[Prototype]]`.

Если изменить свойства `User.prototype`, существующие экземпляры увидят изменения через прототипную цепочку.

Если же полностью заменить `User.prototype` другим объектом, это повлияет только на новые экземпляры. У старых останется ссылка на прежний прототип.

Важно: `User.prototype` и `Object.getPrototypeOf(User)` - разные вещи. Второе выражение возвращает прототип самой функции.

# Как работают классы JavaScript поверх прототипов?

Классы JavaScript используют прототипное наследование, предоставляя более удобный синтаксис для создания объектов и организации наследования.

```
class Animal {
  speak() {
    return "Sound";
  }
}

class Dog extends Animal {
  bark() {
    return "Woof";
  }
}
```

При этом:

- `speak()` находится в `Animal.prototype`.
- `bark()` находится в `Dog.prototype`.
- `Dog.prototype` наследуется от `Animal.prototype`.
- Экземпляры `Dog` получают доступ к обоим методам через прототипную цепочку.

Ключевое слово `extends` связывает прототипы экземпляров и самих конструкторов, обеспечивая также наследование статических методов.

`super` позволяет обращаться к родительскому конструктору или методам.

Методы, объявленные в теле класса, обычно размещаются в прототипе и разделяются экземплярами. Поля класса, напротив, создаются непосредственно у каждого экземпляра.

# Чем `class` отличается от функции-конструктора?

Оба механизма позволяют создавать экземпляры и использовать прототипное наследование, но имеют важные различия.

| `class`                                            | Функция-конструктор                                                            |
|----------------------------------------------------|--------------------------------------------------------------------------------|
| Нельзя вызвать без `new`                           | Обычную функцию можно вызвать без `new`                                        |
| Тело класса выполняется в строгом режиме           | Строгий режим зависит от контекста                                             |
| Методы неперечисляемые                             | Методы, присвоенные через `prototype.method = ...`, перечисляемые по умолчанию |
| Поддерживает `extends`, `super`, `#private`        | Наследование и приватность требуют других механизмов                           |
| Объявление класса находится в TDZ до инициализации | Function declaration доступна до объявления                                    |

Кроме того, классы поддерживают публичные поля, приватные элементы, статические блоки и инициализаторы.

Несмотря на различия, классы в JavaScript остаются функциями-конструкторами, использующими прототипы.

# Как реализовать приватные поля класса?

Приватные поля объявляются с префиксом `#` и доступны только внутри тела класса, который их объявил.

```
class User {
  #password;

  constructor(password) {
    this.#password = password;
  }

  checkPassword(value) {
    return this.#password === value;
  }
}

const user = new User("12345");

user.checkPassword("12345"); // true
// user.#password; // SyntaxError
```

Особенности:

- Приватные поля нельзя прочитать или изменить снаружи через обычный доступ к свойствам.
- Они не доступны через `Object.keys()`, `Reflect.ownKeys()` или `Object.getOwnPropertyNames()`.
- Подклассы не получают прямого доступа к приватным полям родителя.
- Поддерживаются также приватные методы и статические приватные элементы.

Приватность обеспечивается самим JavaScript, а не только проверкой типов.

Например, модификатор `private` в TypeScript без `#` обычно обеспечивает лишь проверку на этапе компиляции.

# Чем `Object.keys()`, `Object.values()` и `Object.entries()` различаются?

Все три метода возвращают массивы, содержащие информацию о собственных перечисляемых свойствах объекта со строковыми ключами.

- `Object.keys(obj)` - массив ключей.
- `Object.values(obj)` - массив значений.
- `Object.entries(obj)` - массив пар `[key, value]`.

```
const user = { name: "Alex", age: 25 };

Object.keys(user);
// ["name", "age"]

Object.values(user);
// ["Alex", 25]

Object.entries(user);
// [["name", "Alex"], ["age", 25]]
```

Все три метода используют одинаковый порядок ключей.

Они игнорируют унаследованные, неперечисляемые свойства и свойства с ключами типа `Symbol`.

Для получения всех собственных ключей, включая символы и неперечисляемые свойства, используется `Reflect.ownKeys()`.

# Чем `in` отличается от `Object.hasOwn()`?

Оператор `in` проверяет существование свойства во всём объекте, включая прототипную цепочку.

`Object.hasOwn()` проверяет наличие свойства непосредственно у объекта.

```
const parent = { role: "admin" };
const user = Object.create(parent);

user.name = "Alex";

"role" in user;           // true
Object.hasOwn(user, "role"); // false

Object.hasOwn(user, "name"); // true
```

Оба механизма учитывают неперечисляемые свойства и символьные ключи.

Наличие свойства не зависит от его значения: если свойство существует и содержит `undefined`, обе проверки могут вернуть `true`.

`Object.hasOwn()` предпочтительнее прямого вызова `obj.hasOwnProperty()`, поскольку работает даже с объектами без прототипа или с переопределённым методом `hasOwnProperty`.

# Как работают property descriptors и `Object.defineProperty()`?

Property descriptor - набор характеристик свойства, определяющих его значение и поведение.

Существуют два вида дескрипторов.

Data descriptor:

- `value` - значение свойства.
- `writable` - возможность изменять значение.

Accessor descriptor:

- `get` - функция чтения значения.
- `set` - функция установки значения.

Общие характеристики:

- `enumerable` - участвует ли свойство в перечислении.
- `configurable` - можно ли удалить свойство или изменить его конфигурацию.

`Object.defineProperty()` создаёт или изменяет собственное свойство с заданным дескриптором.

```
const user = {};

Object.defineProperty(user, "id", {
  value: 123,
  writable: false,
  enumerable: false,
  configurable: false
});
```

Здесь `id` нельзя переназначить обычным присваиванием, удалить или перечислить через `Object.keys()`.

Важная особенность: при создании свойства через `Object.defineProperty()` неуказанные булевы характеристики по умолчанию равны `false`.

Для обычных свойств, создаваемых присваиванием, `writable`, `enumerable` и `configurable` по умолчанию равны `true`.

# Чем getter и setter отличаются от обычных свойств?

Обычное свойство непосредственно хранит значение.

Getter - функция, вызываемая при чтении свойства.

Setter - функция, вызываемая при присваивании значения свойству.

```
const user = {
  firstName: "Alex",
  lastName: "Smith",

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    [this.firstName, this.lastName] = value.split(" ");
  }
};

user.fullName; // "Alex Smith"

user.fullName = "John Doe";
user.firstName; // "John"
```

Getter позволяет вычислять значение динамически, а setter - контролировать или преобразовывать присваиваемые данные.

В отличие от обычного свойства, accessor-свойство само по себе не имеет слота `value`. Getter и setter определяют его поведение и не обязаны что-либо сохранять.

Важно учитывать, что чтение getter может вызывать побочные эффекты, поэтому такое свойство не всегда ведёт себя как обычное поле.

# Что делают `Object.freeze()`, `Object.seal()` и `Object.preventExtensions()`?

Эти методы ограничивают возможность изменения объекта.

| Метод                        | Добавление | Удаление | Изменение значений обычных свойств |
|------------------------------|------------|----------|------------------------------------|
| `Object.preventExtensions()` | Нет        | Да       | Да                                 |
| `Object.seal()`              | Нет        | Нет      | Да, если `writable: true`          |
| `Object.freeze()`            | Нет        | Нет      | Нет                                |

`Object.preventExtensions()` запрещает добавлять новые собственные свойства.

`Object.seal()` дополнительно делает существующие собственные свойства неконфигурируемыми.

`Object.freeze()` дополнительно делает собственные data-свойства недоступными для записи.

Все три метода работают поверхностно.

```
const user = {
  profile: {
    name: "Alex"
  }
};

Object.freeze(user);

user.profile.name = "John"; // Работает
```

Заморозка не распространяется автоматически на вложенные объекты.

Также `Object.freeze()` не отключает существующие setter-функции и не замораживает внутреннее состояние таких коллекций, как `Map` и `Set`.

# Чем поверхностное копирование отличается от глубокого?

Поверхностное копирование (shallow copy) создаёт новый объект, но сохраняет ссылки на вложенные объекты.

```
const original = {
  profile: { name: "Alex" }
};

const copy = { ...original };

copy.profile.name = "John";

original.profile.name; // "John"
```

Верхнеуровневые объекты разные, но `original.profile` и `copy.profile` указывают на один объект.

Глубокое копирование (deep copy) создаёт независимые копии вложенных изменяемых структур, исключая совместное использование соответствующих ссылок.

```
const copy = structuredClone(original);

copy.profile.name = "John";

original.profile.name; // "Alex"
```

Для поверхностного копирования обычно используют spread-синтаксис, `Object.assign()`, `Array.slice()`.

Для глубокого - `structuredClone()` или специализированные решения.

При этом глубокое копирование не обязательно сохраняет прототипы, методы, дескрипторы и другие особенности исходных объектов. Это зависит от используемого механизма.

# Когда подходит `structuredClone()` и какие значения он не клонирует?

`structuredClone()` выполняет глубокое клонирование значений, поддерживаемых алгоритмом structured clone.

Подходит для копирования сложных структур данных, включая:

- Обычные объекты и массивы.
- `Map`, `Set`, `Date`, `RegExp`.
- `ArrayBuffer`, типизированные массивы.
- Циклические ссылки.
- Некоторые другие встроенные типы.

```
const original = {
  date: new Date(),
  items: new Map([["a", 1]])
};

const copy = structuredClone(original);
```

Ограничения:

- Не клонирует функции.
- Не клонирует значения типа `Symbol`.
- Не поддерживает DOM-узлы.
- Не сохраняет пользовательские прототипы классов.
- Не сохраняет property descriptors, getter/setter и приватные элементы классов как таковые.

При попытке клонировать неподдерживаемое значение обычно возникает `DataCloneError`.

Дополнительно поддерживается передача владения (transfer) для некоторых объектов, например `ArrayBuffer`. В таком случае исходный буфер отсоединяется, а его содержимое передаётся результату без обычного копирования данных.

# Чем `Map` отличается от `Object`?

`Map` - коллекция пар ключ-значение, предназначенная для динамического хранения и поиска данных.

Основные различия:

| Характеристика       | `Map`                                  | `Object`                              |
|----------------------|----------------------------------------|---------------------------------------|
| Тип ключей           | Любые значения                         | `string` и `Symbol`                   |
| Количество элементов | `size`                                 | Через `Object.keys()` и другие методы |
| Итерация             | Встроенный итератор                    | Нужны дополнительные механизмы        |
| Порядок ключей       | Порядок добавления                     | Специальные правила                   |
| Прототипные свойства | Не смешиваются с записями              | Могут наследоваться                   |
| API                  | `set`, `get`, `has`, `delete`, `clear` | Доступ и операции над свойствами      |

```
const map = new Map();

const key = { id: 1 };

map.set(key, "value");

map.get(key); // "value"
```

`Map` сравнивает ключи по алгоритму `SameValueZero`. Для объектов это означает сравнение по идентичности ссылки.

Когда использовать:

- `Map` - для динамических коллекций, частых операций добавления и удаления, ключей произвольных типов.
- `Object` - для структурированных сущностей с заранее известными полями, конфигураций и JSON-подобных данных.

# Чем `Set` отличается от массива?

`Set` - коллекция уникальных значений, сохраняющая порядок их первого добавления.

В отличие от массива:

- Автоматически исключает дубликаты.
- Не поддерживает доступ по числовому индексу.
- Предоставляет методы `add()`, `has()`, `delete()`, `clear()`.
- Обычно обеспечивает более эффективную проверку существования элемента, чем `Array.includes()` на больших коллекциях.

```
const values = new Set([1, 2, 2, 3]);

[...values]; // [1, 2, 3]

values.has(2); // true
```

Уникальность определяется через `SameValueZero`:

- `NaN` считается равным `NaN`.
- `0` и `-0` считаются одинаковыми.
- Объекты сравниваются по ссылке.

Массив лучше подходит для упорядоченных последовательностей с индексами и повторяющимися значениями.

`Set` - для уникальных элементов и проверки принадлежности коллекции.

# Для чего нужны `WeakMap` и `WeakSet`?

`WeakMap` и `WeakSet` - коллекции, которые не удерживают свои ключи или элементы от сборки мусора.

`WeakMap` хранит пары ключ-значение. Ключами могут быть объекты и нерегистрированные символы.

`WeakSet` хранит уникальные объекты и нерегистрированные символы без связанных значений.

```
const metadata = new WeakMap();

let user = { name: "Alex" };

metadata.set(user, { visits: 10 });

user = null;
```

Если на первоначальный объект больше нет сильных ссылок, он может быть удалён сборщиком мусора вместе с соответствующей записью `WeakMap`.

Основные особенности:

- Не поддерживают перебор элементов.
- Не имеют свойства `size`.
- Не позволяют получить список всех ключей или элементов.
- Не препятствуют сборке мусора для ключей и элементов, которые больше не используются.

Отсутствие итерации связано с тем, что состав коллекции зависит от работы сборщика мусора.

Применение: хранение метаданных объектов, кеширование результатов и учёт состояний без необходимости вручную удалять записи после уничтожения объектов.

# Почему два объекта с одинаковыми полями обычно не равны по `===`?

Объекты JavaScript сравниваются через `===` по идентичности, а не по содержимому.

```
const a = { x: 1 };
const b = { x: 1 };

a === b; // false

const c = a;

a === c; // true
```

`a` и `b` - разные объекты, несмотря на одинаковую структуру.

`a` и `c` ссылаются на один объект, поэтому сравнение возвращает `true`.

Так же работают сравнения массивов и функций.

Для сравнения объектов по содержимому требуется отдельный алгоритм, учитывающий вложенность, типы и другие особенности данных.

`Object.is()` тоже сравнивает объекты по идентичности.

# Какие особенности есть у порядка перечисления ключей объекта?

Для собственных ключей обычного объекта JavaScript использует определённый порядок:

1. Строковые ключи, являющиеся индексами массива, - по возрастанию числового значения.
2. Остальные строковые ключи - в порядке создания свойств.
3. Символьные ключи - в порядке создания.

```
const obj = {
  b: 1,
  10: "ten",
  2: "two",
  a: 2
};

Object.keys(obj);
// ["2", "10", "b", "a"]
```

Особенности:

- `"2"` считается индексным ключом, а `"02"` - нет.
- `Object.keys()` возвращает только собственные перечисляемые строковые ключи.
- `Reflect.ownKeys()` возвращает все собственные ключи, включая символы.
- `for...in` также перебирает перечисляемые унаследованные свойства.

`Map`, в отличие от обычных объектов, сохраняет порядок добавления для всех типов ключей, без отдельной сортировки числовых ключей.

# Что такое `Proxy` и `Reflect`?

`Proxy` - механизм перехвата и переопределения операций над объектом.

Позволяет перехватывать чтение, запись, удаление свойств, вызов функций, проверку наличия свойств и другие операции.

```
const user = { name: "Alex" };

const proxy = new Proxy(user, {
  get(target, key, receiver) {
    console.log(`Reading ${String(key)}`);

    return Reflect.get(target, key, receiver);
  }
});

proxy.name;
// Reading name
// "Alex"
```

`Reflect` - встроенный объект с методами для выполнения стандартных операций над объектами.

Например:

- `Reflect.get()` - чтение свойства.
- `Reflect.set()` - запись свойства.
- `Reflect.has()` - проверка наличия.
- `Reflect.deleteProperty()` - удаление.
- `Reflect.ownKeys()` - получение собственных ключей.

`Reflect` часто используется внутри ловушек `Proxy`, чтобы сохранить стандартное поведение операции.

Ограничения `Proxy`: ловушки обязаны соблюдать инварианты JavaScript. Например, нельзя сообщать некорректные сведения о некоторых неконфигурируемых свойствах.

Кроме того, Proxy не полностью прозрачен для объектов со специальными внутренними слотами, например `Map` или `Date`: некоторые встроенные методы могут не работать без корректной привязки `this`.

# Какие ограничения есть у `JSON.stringify()` и `JSON.parse()`?

`JSON.stringify()` сериализует JavaScript-значения в строку JSON, а `JSON.parse()` преобразует JSON-строку обратно в значения JavaScript.

Основные ограничения сериализации:

- `undefined`, функции и символы пропускаются в объектах, а в массивах превращаются в `null`.
- `NaN`, `Infinity`, `-Infinity` превращаются в `null`.
- `BigInt` по умолчанию вызывает `TypeError`, если не задана специальная сериализация.
- Циклические ссылки вызывают `TypeError`.
- `Map` и `Set` по умолчанию не сериализуют своё содержимое.
- `Date` обычно преобразуется в строку ISO через `toJSON()`.
- Прототипы, методы и дескрипторы свойств не сохраняются.

```
JSON.stringify({
  a: undefined,
  b: NaN,
  c: new Set([1, 2])
});

// '{"b":null,"c":{}}'
```

`JSON.parse()` восстанавливает данные в виде обычных объектов, массивов и примитивов, но не возвращает исходные экземпляры классов и специальные типы.

Для настройки поведения применяются `replacer` в `JSON.stringify()` и `reviver` в `JSON.parse()`.

Важно: JSON не является универсальным механизмом глубокого копирования объектов.

# Как работают `Symbol.toPrimitive` и приведение объекта к примитиву?

Когда JavaScript требуется преобразовать объект в примитив, используется внутренний алгоритм `ToPrimitive`.

Объект может определить собственное поведение через метод `Symbol.toPrimitive`.

```
const user = {
  name: "Alex",

  [Symbol.toPrimitive](hint) {
    if (hint === "number") return 100;
    return this.name;
  }
};

Number(user); // 100
String(user); // "Alex"
```

Метод получает аргумент `hint`, определяющий ожидаемый тип:

- `"string"` - предпочтительно строка.
- `"number"` - предпочтительно число.
- `"default"` - тип не задан однозначно.

`Symbol.toPrimitive` должен вернуть примитив, иначе возникнет `TypeError`.

Если метод отсутствует, JavaScript использует стандартное преобразование через `valueOf()` и `toString()`.

Для строкового контекста обычно первым вызывается `toString()`, для числового - `valueOf()`. При `hint: "default"` большинство обычных объектов используют числовой порядок, но существуют исключения, например `Date`.

Приведение происходит при арифметических операциях, сравнении, конкатенации и других операциях, требующих примитивных значений.

# Что означает иммутабельное обновление вложенного объекта?

Иммутабельное обновление - создание новой структуры данных с необходимыми изменениями без модификации исходной.

При работе с вложенными объектами требуется копировать каждый уровень по пути к изменяемому значению.

```
const state = {
  user: {
    profile: {
      name: "Alex",
      age: 25
    }
  }
};

const nextState = {
  ...state,
  user: {
    ...state.user,
    profile: {
      ...state.user.profile,
      name: "John"
    }
  }
};
```

В результате:

```
state.user.profile.name;     // "Alex"
nextState.user.profile.name; // "John"

state === nextState; // false
```

При этом неизменённые вложенные объекты могут сохранять прежние ссылки. Этот подход называется structural sharing.

Он позволяет избежать полного глубокого копирования и упрощает определение изменений через сравнение ссылок.

Такой принцип широко используется в React, Redux и других системах управления состоянием, где идентичность объектов помогает обнаруживать обновления.

# Почему не стоит без необходимости изменять прототипы встроенных объектов?

Изменение прототипов встроенных объектов, например `Array.prototype` или `Object.prototype`, влияет на все объекты, наследующие от них.

```
Array.prototype.first = function () {
  return this[0];
};
```

Основные проблемы:

- Конфликты имён. Добавленный метод может совпасть с методом библиотеки или будущего стандарта JavaScript.
- Глобальные побочные эффекты. Изменение поведения распространяется на всю среду выполнения в пределах соответствующего JavaScript realm.
- Проблемы совместимости. Сторонний код может предполагать стандартную структуру прототипов.
- Безопасность. Неконтролируемая модификация прототипов связана с рисками prototype pollution.
- Производительность. Изменения прототипов могут нарушать оптимизации JavaScript-движка.

Особенно опасно изменять `Object.prototype`, поскольку от него наследуется большинство обычных объектов.

Исключением могут быть тщательно реализованные полифилы, которые добавляют отсутствующие стандартные возможности с соблюдением требований спецификации.

В обычном приложении предпочтительнее использовать отдельные функции и собственные классы, не изменяя встроенные прототипы.
